# S04 离线 Spark 作业

入口为 `python -m analytics.spark_job`，必须给固定输入路径、输出根目录和任务 ID。它不导入应用数据库模块、不连接 MySQL、不启动模型或 Web 服务。依赖沿用已安装的 WSL PySpark 4.2.0、Python 3.12.3 和 JDK 17。

## 复跑

在仓库根目录对应的 WSL 目录执行；将输出放到新的任务目录，`job-id` 必须未成功使用。

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export PYSPARK_PYTHON=/home/administrator/scholarhub-analytics/.venv/bin/python
export PYSPARK_SUBMIT_ARGS='--driver-memory 2g pyspark-shell'
/home/administrator/scholarhub-analytics/.venv/bin/python -B -m analytics.spark_job \
  --input '开发相关文档/阶段报告/AI大数据改造/V2/S03-ODS/snapshots/s03-owner3-restored' \
  --output /home/administrator/scholarhub-analytics/s04-20261020 \
  --job-id my-new-s04-run
```

SparkSession 使用 local[2]、shuffle 分区 8、UTC session timezone。运行版本、参数、源窗口、cutoff、输入 batch_id 记录在任务 manifest 中。这是本机单机实验，不称为集群部署。

## 输入边界和质量

正式输入必须是 S03 `snapshots/<id>` 的完整 manifest 与 JSONL，先核对行数／字节。测试入口另外允许明确给出的 S03 `small/<case>/input.json`，其 snapshot_id 固定为 fixture-<case>，不冒充真实业务抽取。

Schema 继承 S01 的 10 表 71 字段；source_claim_projection 与 AI 辅助 9 字段单独声明。解析 JSON 在 Python 驱动端完成，加载成本包含在计时中；随后规范化、去重、关系、事实和聚合均由真实 Spark 执行。该入口适用于当前获准的本机实验档；不声称具备超出驱动内存的分布式输入能力。

质量输出逐表含 raw_rows、invalid_rows、unique_rows、exact_duplicates。`raw=invalid+unique+exact_duplicates` 必须成立。unique 是通过字段级校验的去重行，后续关系或主键冲突仍可使整批失败，不能将它直接称为全部有效业务事实。

异常集合保留 table_name、source_key、source_row（可取得时）、reason，不复制正文。同主键不同内容、版本号冲突、悬空引用、错主体、错班级／教师、断裂版本链、状态与反馈矛盾均阻止完成。完全相同行按字段规范化后去重并计数。历史学习分钟允许非负整数；1440 是现有写入 API 限制，不擅自用它删除历史库的合法较大值。NULL／0 分开；Token 和耗时 NULL 原样进入辅助 DWD。

## DWD 字典

| Parquet | 主键／来源 | 新增计算字段 |
| --- | --- | --- |
| dwd/record_facts | learning_records.id；可追溯 feedback_id、submission_id、version_number | metric_date、source_kind=ordinary/trusted_teaching/unverified_claim |
| dwd/task_facts | daily_tasks.id | metric_date保留scheduled_date；overdue_unfinished；整行是当前快照状态 |
| dwd/cohort_facts | submissions.id → submission_id | 最新版本ID、版本数减一、revised/confirmed/pending_latest、first_feedback_id/version、first_wait_minutes、missing_teaching_record_links |
| dwd/ai_requests_aux | 本人请求id，保持9字段及NULL | 仅追溯标签，不参与三类核心指标 |

每份 Parquet 加 snapshot_id、job_id、rule_version。可信来源必须有真实 ACCEPT、匹配 accepted 版本、正确班级教师、学生及记录归属；JSON 声明不决定来源。教师确认不依赖学习记录仍存在，SET NULL 仅增加关联缺失。

## ADS 字典与专题

| 输出 | 含义 |
| --- | --- |
| ads_records | owner、去重记录／已知分钟／已知和缺失数／已知零／活跃日／来源分类 |
| ads_tasks | owner、总数、完成、取消、逾期未完、精确6位percent、严格完成资格 |
| ads_topic | 固定V1群组、修订／教师确认／首次通过／修订后通过／待评、反馈等待覆盖与4区间、缺失关联；精确分子分母 |
| ads_daily | owner和业务日；三事实层各自先聚合再合并，日期是事件日或任务计划日，不是历史收盘状态 |
| ads/answers.json | 按owner组织的三类汇总和每日行；数值由上述Spark SQL结果组装 |
| ads/conclusions.json | 固定描述性规则：修订、首次通过反例、待评、未知时长、空任务；保留条件、触发／未触发、样本量、日期和DWD引用 |

时间窗口使用上海起始日零点至结束次日零点换成 UTC，右开；同时受 source_cutoff 约束。scheduled_date 直接使用 DATE。提交以 V1 业务日进入群组，使用完整版本链的最新状态。首次反馈等待取最早反馈及其对应版本，不把后续 ACCEPT 时间误当首次等待；无反馈为 NULL。

百分比在 SQL 使用 Decimal 计算并保留6位，展示按 HALF_UP 1位，保留分子分母。分母0返回NULL；空集合分钟和为0同时known_count=0；199/200保持99.500000%，不具备完成资格。

## 任务协议及 S05 交接

每次尝试进入 `.incomplete/<job-id>-<attempt>`；质量失败或中途失败保留 failure.json，不能消费该目录。成功先完成全部 DWD/ADS/quality/lineage/manifest，再同文件系统改名到 `jobs/<job-id>`，重复ID直接拒绝。重试使用新的未完成尝试，不删除故障证据、不改旧成功目录。

作业 manifest 的 computed 只表示计算成功。独立验收结果在完成目录**之外**的 `<job-id>-acceptance.json`，state=validated；验证器不会改写完成产物。S05 应同时核对完成 manifest、验收、对应 snapshot 和规则版本，不能单凭存在 Parquet 发布。synthetic 始终只做离线实验。

目前仅批准 quality-1.0 与 learning-process-1.0。未知规则版本明确拒绝；不能通过随意换版本字符串执行未经批准的公式。规则真正变化后需要批准对应规则实现、新版本及新任务ID，已有成功结果保持。

## 评价边界

S04 对照冻结数据断言和独立 Python，验证正确性及规则证据。S01 的正式 J1 专题语言评分在 S06，当前无模型调用授权，不填写该分数；S05 的发布与权限10分同样不由本阶段冒领。

性能记录是当前输入和参数下的一次正确性运行，包含输入读取、规范／关联、ADS和写文件。Python重新读取相同文件，完整采用同一关系、窗口、NULL规则，参考实现每主体重复预检全部关系，该成本明确记录；不据此宣称通用速度优势。三轮进程冷／热与中位数、扩大规模实验按S06执行。
