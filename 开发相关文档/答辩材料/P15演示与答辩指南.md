## 1. Windows 启动

在项目根目录打开两个 PowerShell。后端终端：

```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 2. 演示链路

建议使用自己注册的两个演示账号 A、B，不使用数据库 root 作为平台账号。当前没有管理员角色、内置演示密码或免认证入口。记录这次演示创建的资源 ID，避免修改已有学习数据。

| 顺序 | 页面或接口 | 操作与可检查结果 |
| --- | --- | --- |
| 1 | `/register`、`/login`、`/profile` | 注册 A、登录，查看当前用户；错误密码应失败，不返回密码 hash。 |
| 2 | `/community` | 浏览真实已发布项目；空列表属于正常状态。 |
| 3 | `/projects`、`/projects/:id` | 新建校园学习实践项目，填写 Python/FastAPI/Vue/MySQL、需求和输出要求；刷新详情确认持久化。 |
| 4 | `/workspace/dashboard`、`/workspace/projects` | 查看当前用户的任务、项目与学习数据，不用硬编码统计补充页面。 |
| 5 | `/workflows`、`/workflows/:id` | 关联项目，添加需求分析、技术栈分析、架构设计，拖拽连成 DAG；保存后刷新确认节点、配置和位置恢复。 |
| 6 | Swagger 的 ProjectContext 接口 | 创建、读取 Context，检查核心字段、版本、时间和来源。 |
| 7 | Swagger 的 Agent 接口 | 调用项目分析和 Prompt Agent，查询持久化结果；模型内容仅作为建议，不执行代码。 |
| 8 | Swagger 的 Workflow run 接口 | 使用最新版本运行三节点，查询 WorkflowRun；改为 Java/Spring Boot，检查下游 stale 后重新生成。 |
| 9 | `/learning`、`/learning/tasks` | 创建课程、计划和关联项目的任务，完成任务后计划进度更新。 |
| 10 | `/learning/records`、`/workspace/records` | 保存 `project` 类型开发记录与 `study` 学习记录，填写实际时长；刷新后记录存在。 |
| 11 | `/analytics` | 切换 7/30 日，核对学习记录和项目、社区聚合口径；生成报告并刷新查询。等待期间按钮禁用，失败显示可重试状态。 |
| 12 | `/projects/:id` → `/community` | A 发布项目，B 浏览、点赞、评论、收藏；重复点赞/收藏不重复计数。 |
| 13 | 另一个浏览器会话或 Swagger | 用 B 访问 A 私有项目返回 403，读取 A 的 AI/报告结果返回 404；取消发布后社区详情不可读。 |

P10-P13 的 Context、独立 Agent 和引擎运行已提供 API，但当前没有对应完整前端操作面板；工作流前端结果面板实际是“图检查”。答辩使用“页面 + Swagger”组合演示，不宣称全部能力都有页面。P15 不新增这些功能页。

### Swagger 关键请求

先通过登录页完成滑块验证并登录，或在 Swagger 依次调用 `POST /api/v1/auth/slider/challenge`、`POST /api/v1/auth/slider/verify`（提交 `challenge_id`、`position: 100`），将返回的 `slider_token` 连同账号密码提交到 `POST /api/v1/auth/login`。挑战 120 秒内有效且至少存续 0.5 秒，验证凭证 60 秒内有效且仅可用于一次登录。然后在 Swagger 的 Authorize 输入返回的 JWT；不要将凭证写入文档。所有 ID 和版本都取自当前响应。

滑块为基础演示级交互：后端校验凭证和有效期，但客户端可脚本化完成位置提交，不代表专业反机器人能力。当前挑战只存单 worker 内存，重启或热重载后需要重新验证；多实例部署需另行设计共享挑战存储和防滥用措施。

创建 Context：`POST /api/v1/projects/{project_id}/context`，无请求体。再次读取使用 `GET`；更新前重新读取版本。

分析请求 `POST /api/v1/agents/project-analysis`：

```json
{
  "project_id": 1,
  "input": { "focus": "拆解校园学习实践的需求、难点和验收步骤" }
}
```

Prompt 请求 `POST /api/v1/agents/prompt`：

```json
{
  "project_id": 1,
  "input": {
    "task": "实现学习记录页面",
    "environment": "Windows 本地开发",
    "description": "页面通过已认证的 FastAPI 接口保存记录",
    "coding_standards": ["TypeScript 不使用 any", "后端服务与仓储分层"],
    "api_requirements": ["/api/v1/learning/records"]
  }
}
```

用响应的 `request_id` 调用 `GET /api/v1/agents/results/{request_id}`。Provider 失败或输出不符合 Schema 时展示失败信息，不手工将状态改为成功。

读取 `GET /api/v1/workflows/{workflow_id}/graph`，用 `workflow.version` 请求 `POST /api/v1/workflows/{workflow_id}/run`：

```json
{ "expected_version": 1, "mode": "incomplete" }
```

版本过期或没有可执行节点会返回 409。结果通过 `GET /api/v1/workflows/{workflow_id}/runs/{run_id}` 查询。示例中的 `1` 必须换成实际值。

修改 Context：`PUT /api/v1/projects/{project_id}/context`：

```json
{
  "expected_version": 1,
  "values": { "language": "Java", "framework": "Spring Boot", "backend": "Spring Boot" }
}
```

检查返回的 `stale_node_ids` 与图状态，再读最新图版本重跑。`incomplete` 针对未成功节点及其下游；`all` 明确重新生成整图。生成结果仍须遵守用户约束，不把模型建议当授权。

## 4. 口径与简化边界

- 数据库存 UTC，API 时间使用带时区时间；统计默认由浏览器传 `timezone_offset_minutes`，工作台使用 `date` 和 `utc_offset_minutes`。东八区为 `480`，不要混淆参数名。
- “今日访问人数”是项目浏览表按用户去重，不是网站所有访问者或在线人数。社区互动为浏览、未删除评论、点赞和收藏；重复点赞、收藏保持幂等。
- 平台统计返回匿名全平台聚合；学习报告、任务、记录和私有项目按当前用户隔离。两类范围不能直接相互比较。
- 项目状态 `completed` 与任务计算的进度不同；完成所有任务不自动把项目状态改为 completed。P15 已统一工作台、统计与新报告的进度：只统计项目所有者的关联任务，按 Python `round` 的规则取整，无任务时用项目字段。已有报告保留生成时快照，不回写历史内容。
- P14 不回填迁移前已完成项目的完成时间，历史趋势不应凭空补数。
- 开发记录复用 `LearningRecord.record_type=project`，不是自动 Git 提交采集；另支持 `study/workflow/ai/course/task`。完成任务不自动伪造学习时长。
- 编辑器可展示多类节点，但引擎当前仅注册需求分析、技术栈分析和架构设计，不支持条件分支或任意工具节点。
- 引擎为有界顺序执行：默认最多 12 节点、12 回合、9000 completion tokens、90 秒；无跨进程主动取消接口，遗留运行在下一次请求时按超时规则恢复。
- 报告结构化成功不代表内容天然正确，模型总结仍需人工复核；`failed` 报告可以查询并按规则重试。
- 不含私信、关注、在线 IDE、任意 shell/SQL、自动执行代码或实时协同。没有管理员角色与 Redis 缓存，不以文档宣称已经实现。
