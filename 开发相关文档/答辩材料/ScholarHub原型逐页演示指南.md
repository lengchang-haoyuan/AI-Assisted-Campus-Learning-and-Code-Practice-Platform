# ScholarHub 原型逐页演示指南

**教师展示版｜更新日期：2026-09-25**

> 本文按当前代码、路由和本地开发数据编写，用于向指导教师介绍 ScholarHub 原型。文中把可直接演示的功能、需要特定角色的数据页面和尚未完成的阶段分开说明。

## 1. 先用一句话介绍项目

ScholarHub 是一个面向高校学生的 AI 辅助校园学习与代码实践平台。它把个人项目、学习计划、每日任务、学习记录、校园代码社区、可视化 AI 工作流、数据分析，以及教师布置教学任务放在同一个系统中，让“选项目—做任务—用 AI 辅助—记录学习—展示成果”形成连续过程。

当前原型已完成 P00-P21，能够展示个人学习、项目实践、校园身份、教学班、成果提交与反馈、AI 用户页面和社区人工治理。P22 成本控制、P23 生产部署与隐私、P24 真实班级试点尚未实施。

## 2. 演示前准备

### 2.1 环境检查

- MySQL、FastAPI 后端和 Vue 前端应处于运行状态。
- 前端地址：`http://127.0.0.1:5173/`
- 后端接口文档：`http://127.0.0.1:8000/docs`
- 建议使用常规桌面浏览器宽度，并把浏览器缩放保持在 100%。
- 演示前刷新一次页面，确认登录、项目列表和工作流页面能够读取真实数据库。

### 2.2 当前本地演示数据

| 数据 | 当前数量 | 演示意义 |
| --- | ---: | --- |
| 普通用户 | 2 | 可演示注册后的普通账号与登录流程 |
| Project | 74 | 包含 6 个开源学习案例、50 道 Python 练习和 18 个 Java/C/Vue 入门项目 |
| 有效校园管理员 | 1 | 当前账号可演示校园账号管理 |
| 有效教师 | 0 | 教师页面需先准备已核验教师账号才能完整操作 |
| 有效学生 | 0 | 学生班级视图需先准备学生账号和班级成员关系 |

## 3. 推荐演示路线

### 3.1 10–12 分钟主线

1. 从 `/login` 说明统一登录和滑块验证。
2. 登录后进入 `/`，介绍首页、全局导航和项目概况。
3. 打开 `/projects`，展示 74 个项目案例与 Python、Java、C、Vue 入门练习。
4. 进入一个 `/projects/:id`，展示项目说明、技术栈、需求和交付要求。
5. 打开 `/workflows` 和一个 `/workflows/:id`，演示节点图、六类 AI 节点、运行入口和结果记录。
6. 打开 `/workspace/dashboard` 与 `/learning`，说明个人任务、学习计划和学习证据如何关联。
7. 打开 `/community`，说明项目自愿发布后的互动闭环。
8. 打开 `/analytics`，展示真实聚合统计和 AI 学习报告。
9. 打开 `/campus/admin/accounts`，说明固定角色、定向邀请和审计。
10. 打开 `/campus/classes`，如实说明功能已完成，但当前尚无真实教师、学生和班级数据。

## 4. 全局导航怎么讲

登录后的顶部导航包含“首页、社区、项目库、我的桌面、学习系统、工作流、数据”。拥有有效校园身份后显示“教学班”，有效管理员还会显示“校园管理”。右侧全局搜索会把关键词带到项目库，个人头像进入资料页，退出按钮会清除认证状态并返回登录页。

可以这样介绍：

> 这是学生、教师和管理员共用的一套前端。普通功能保持统一，校园入口根据后端返回的有效身份显示。角色不是写在前端或 JWT 里的固定文字，后端会再次检查校园资格和资源范围。

## 5. 认证与账号页面

### 5.1 登录页 `/login`

**现场动作**

1. 切换左侧“项目实践、学习工作台、校园代码社区”三个主题页签。
2. 输入用户名或邮箱和密码。
3. 完成滑块验证后点击“登录”。

**讲解话术**

> 登录页先介绍平台的三个核心场景，再进入统一账号体系。登录支持用户名或邮箱，滑块凭证为一次性短期凭证；登录失败后需要重新验证，避免重复使用。

**演示边界**

- 受保护页面会把未登录用户带回登录页，并在成功登录后返回原地址。
- 已登录用户再访问登录或注册页，会返回首页。
- 不展示真实密码；滑块通过只表示本次人机校验完成。

### 5.2 注册页 `/register`

**现场动作**

1. 展示用户名、邮箱、密码和确认密码字段。
2. 展开“我有校园邀请凭证”，说明可选的校园加入方式。

**讲解话术**

> 所有人先有普通账号。普通账号可以使用个人项目和学习功能；校园角色需要管理员核验的定向邀请。已有邀请的用户可以在注册时一并兑换，没有邀请也可以正常创建普通账号。

**演示边界**

- 用户名要求 3–50 位字母、数字或下划线，密码至少 8 个字符。
- 邀请凭证不会保存在浏览器中。
- 不要为了现场展示临时创建真实教师或学生账号。

### 5.3 重置密码页 `/reset-password`

**现场动作**

1. 展示重置凭证、新密码和确认新密码三个字段。
2. 说明凭证由管理员核验后签发。

**讲解话术**

> 系统没有默认管理员密码，也不通过明文找回旧密码。管理员只签发一次性重置凭证，用户在这个页面设置新密码；凭证使用后失效，旧会话会被撤销。

**演示边界**

- 当前没有为演示准备一次性重置凭证时，只介绍流程，不提交表单。
- 该页面可以从登录页外访问，因为用户重置密码时通常尚未登录。

### 5.4 个人资料页 `/profile`

**现场动作**

1. 展示用户名、邮箱、账号状态、加入时间和用户编号。
2. 展示当前校园资格；管理员可进入账号管理，普通账号可去兑换邀请。
3. 展开“修改密码”和“撤销全部会话”。

**讲解话术**

> 这里把普通账号和校园资格分开显示。修改密码或主动撤销会话后，其他已登录设备需要重新登录；校园角色变化也会让旧会话失效。

## 6. 首页与个人项目库

### 6.1 首页 `/`

**现场动作**

1. 查看“全部、进行中、已完成”项目筛选。
2. 翻转项目卡片查看技术信息。
3. 启动或重置 25 分钟专注计时器。
4. 指出“项目脉搏”和快速入口。

**讲解话术**

> 首页是登录后的概览入口。项目数量、状态分布和最近更新时间来自当前用户的真实项目。卡片可以快速进入编辑或删除流程，右侧入口连接项目管理、学习桌面和个人资料。

**演示边界**

- 首页的 25 分钟计时器是当前页面的辅助计时，不会自动生成学习记录。
- 删除项目有确认步骤且不可恢复，答辩时不建议实际点击确认。

### 6.2 项目库 `/projects`

**现场动作**

1. 从全局搜索输入“Python”或“字符串”，进入项目库搜索结果。
2. 展示分页项目卡片，以及“创建项目”入口。
3. 打开创建表单，指出名称、难度、状态、说明和技术栈等字段后取消。

**讲解话术**

> 项目库保存当前用户自己的实践项目。现在本地库有 74 个项目，其中包括 50 道从字符串反转开始的 Python 入门练习，以及 18 个 Java、C、Vue 入门项目。搜索、分页、分类封面和空状态都读取真实字段，不是前端写死的卡片。

**字段说明**

- 基础字段：项目名称、难度、状态、项目说明。
- 技术字段：主要语言、核心框架、前端、后端和数据库。
- 教学字段：项目需求按行拆分，交付要求单独记录。

### 6.3 项目详情 `/projects/:id`

**现场动作**

1. 进入一个 Python 练习，展示标题、状态、难度和说明。
2. 查看技术栈、项目需求和交付要求。
3. 指出“编辑项目信息”和“发布到校园代码社区”。

**讲解话术**

> 项目详情把学习素材整理为有规格的项目卡：标题突出，说明、技术栈、需求和交付标准分区展示。用户可以修改自己的项目，也可以选择标签后自愿发布到社区。

**演示边界**

- 发布到社区只开放明确的展示字段，私人学习记录、ProjectContext 和 AI 输入不会公开。
- 社区标签使用逗号分隔，最多 5 个。
- 如果项目已发布，页面提供社区详情入口和撤下社区操作。

## 7. 校园代码社区

### 7.1 社区列表 `/community`

**现场动作**

1. 展示公开项目总数和标签筛选。
2. 在项目卡片上尝试点赞或收藏。
3. 打开一个公开项目。

**讲解话术**

> 社区只显示用户主动发布的项目，按较新的发布记录优先展示。标签帮助学生从语言、框架或兴趣方向发现项目，点赞和收藏状态会写入数据库。

**演示边界**

- 项目库有数据不代表社区一定有公开数据；未发布的私人项目不会出现在这里。
- 页面为空时，可以用空状态说明“自愿发布”的边界，再返回项目库选择项目发布。

### 7.2 社区项目详情 `/community/projects/:id`

**现场动作**

1. 展示发布者、发布时间、浏览、点赞、收藏和评论统计。
2. 查看项目说明、技术铭牌和标签。
3. 输入一条演示评论但不提交，说明评论长度和删除权限。

**讲解话术**

> 社区详情是公开作品的只读展示页，其他用户可以互动，但不能编辑原项目。页面会记录浏览，并提供评论讨论；评论作者或有权限的管理者才能看到删除入口。

## 8. 我的桌面

“我的桌面”侧重今天正在做什么；“学习系统”侧重课程、计划和完整记录。两者使用同一批真实任务、项目和学习记录，只是组织方式不同。

### 8.1 工作台概览 `/workspace/dashboard`

**现场动作**

1. 展示今日已完成任务、已记录分钟、学习进度和进行中项目。
2. 在今日任务中完成一项任务。
3. 打开最近项目和最近记录。

**讲解话术**

> 工作台把今天的任务、投入时长和项目进度放在一页。任务完成后，项目进度会基于关联任务重新计算；学习分钟来自用户主动保存的学习记录。

### 8.2 工作台任务 `/workspace/tasks`

**现场动作**

1. 查看分页任务列表。
2. 打开“创建任务”，展示标题、说明、日期、优先级、时间、预计时长和关联项目。
3. 对一项未完成任务点击“完成”。

**讲解话术**

> 任务可以关联项目，也可以作为独立学习事项。系统独立校验时间范围和预计时长，完成状态会保存在数据库中，刷新后保持一致。

### 8.3 项目进度 `/workspace/projects`

**现场动作**

1. 展示每个项目的状态、难度、完成比例、关联任务数和学习分钟。
2. 进入一个项目进度详情。

**讲解话术**

> 这里不手工填写百分比。项目进度由关联任务的真实完成情况计算，同时显示来自学习记录的累计分钟。

### 8.4 项目进度详情 `/workspace/projects/:id`

**现场动作**

1. 展示进度条、关联任务、已完成数和学习分钟。
2. 查看近期任务与最近 8 条以内的学习记录。
3. 从页面跳转到任务管理或新增记录。

**讲解话术**

> 详情页把一个项目的行动和学习证据合并查看。完成任务会更新进度，学习记录只反映用户实际填写的投入，不由 AI 自动补造。

### 8.5 工作台学习记录 `/workspace/records`

**现场动作**

1. 展示时间线和记录总数。
2. 打开“记录学习”，查看标题、内容、类型、时长、关联项目和发生时间。

**讲解话术**

> 工作台中的学习记录适合快速新增和回看。项目实践类型必须关联项目，自主学习可以不关联项目；时长范围和时间格式由前后端共同校验。

## 9. 学习系统

### 9.1 课程与学习计划 `/learning`

**现场动作**

1. 展示课程数量和进行中计划数量。
2. 打开“新建课程”和“新建计划”表单。
3. 查看计划进度、日期范围，以及课程的编辑和删除入口。

**讲解话术**

> 课程用于记录学习主题和课程信息，学习计划把课程或项目放进明确的日期范围。它们属于个人数据，加入教学班不会把个人课程自动公开，也不会自动复制成全班任务。

### 9.2 每日任务 `/learning/tasks`

**现场动作**

1. 创建或编辑一项任务，关联计划或项目。
2. 点击“完成”，观察本页完成数量变化。
3. 展示分页、失败重试和空状态。

**讲解话术**

> 每日任务是学生自己安排的行动，与教师发布的教学任务是两类独立数据。任务完成和计划进度在同一事务中更新，避免只改一个页面数字。

### 9.3 学习记录 `/learning/records`

**现场动作**

1. 新建、编辑或删除一条学习记录。
2. 查看记录类型、学习分钟和关联对象。

**讲解话术**

> 这页提供学习记录的完整维护能力，而工作台记录页更偏快速查看。记录会成为数据分析和 AI 学习报告的事实来源，但不会自动代表教学任务通过。

## 10. 可视化 AI 工作流

### 10.1 工作流列表 `/workflows`

**现场动作**

1. 选择所属项目，填写工作流名称和说明。
2. 创建工作流后查看修订版本、节点数、连线数和更新时间。
3. 进入编辑器；删除按钮只说明，不实际删除。

**讲解话术**

> 每个工作流属于当前用户的一个项目。列表保存的是后端工作流记录，版本、节点数和连线数不是页面临时状态。

### 10.2 工作流编辑器 `/workflows/:id`

**现场动作**

1. 从节点库添加节点，把节点拖到画布并建立连线。
2. 选择节点，填写名称、指令、预期输出；教学节点按需填写代码。
3. 查看“图检查”，确认引用、重复边、自环和循环检查。
4. 点击“保存工作流”或“保存并运行 AI”。
5. 在“AI 运行与结果”中查看运行历史、节点状态、耗时、Token 用量和结构化输出。
6. 切换“继续未完成的节点”和“重新运行全部节点”。

**六类可运行节点**

| 节点 | 用途 | 展示重点 |
| --- | --- | --- |
| 需求分析 | 整理目标、约束和验收标准 | 把项目描述转为可执行要求 |
| 技术栈分析 | 评估前后端、数据与工程方案 | 给出选择与理由 |
| 架构设计 | 划分模块、边界和数据流 | 形成结构化架构建议 |
| 解题提示 | 从题意给出分层思路和边界 | 适合 Python 练习，不直接替学生完成 |
| 代码讲解 | 解释代码步骤和 Python 概念 | 需要填写待分析代码 |
| 答案评审 | 静态检查答案并给出测试建议 | 不执行代码，不等于自动判题通过 |

**讲解话术**

> 系统保留当前 Provider、Agent 和 Workflow Engine。前端负责画布和配置，后端校验 DAG、准备项目上下文、调用 DeepSeek，并把请求、结果和运行记录持久化。页面刷新后仍能查看历史，失败时可以继续未完成节点。

**演示边界**

- 使用真实 DeepSeek 前先确认后端已配置 API，避免现场才发现网络或额度问题。
- “全部重跑”会再次调用模型并产生用量。
- 不把模型输出说成测试通过、教师评价或项目完成证明。
- 不在代码输入框粘贴密钥、个人隐私或不应发送给外部模型的数据。

## 11. 数据分析页 `/analytics`

**现场动作**

1. 展示今日访问人数、完成任务人数、平台项目、已发布项目、社区互动和平均进度。
2. 查看学习与社区活跃趋势、项目变化、状态分布和技术栈使用情况。
3. 选择日期范围生成 AI 学习报告，或打开已有报告。

**讲解话术**

> 图表数据由后端从 MySQL 聚合，按数据库 UTC 时间统计，再按浏览器时区展示。AI 学习报告只发送当前用户的聚合指标；失败记录可以按同一周期重试，页面不会补造历史活动。

**演示边界**

- “学习分钟、活跃天数、任务完成率”来自已有记录，不代表教师成绩。
- AI 报告与教师反馈、教学任务状态和项目完成状态相互独立。

## 12. 校园身份与教学页面

### 12.1 校园身份 `/campus/join`

**当前账号可直接演示**

页面会显示当前资格、角色、状态和身份版本，并提供“进入教学班”入口；管理员还会看到“进入账号管理”。

**无校园身份时的流程**

用户输入管理员定向签发、且与当前账号或邮箱匹配的邀请凭证。兑换成功后系统要求重新登录，使新的校园资格进入后续授权判断。

### 12.2 校园账号管理 `/campus/admin/accounts`

**现场动作**

1. 展示签发学生或教师邀请：目标账号/邮箱、角色、有效小时和核验原因。
2. 搜索账号，查看账号启停、校园资格和固定角色。
3. 指出暂停、恢复、撤销、角色调整和密码重置凭证。
4. 查看最近邀请和账号审计。

**讲解话术**

> 管理员管理账号元数据、校园资格和一次性凭证。每项敏感操作都需要原因并带版本保护，角色或账号状态变化后旧会话失效。管理员默认不能读取私人项目、笔记、ProjectContext、AI 输入或教学任务正文。

**演示边界**

- 管理员只能直接签发学生或教师邀请；管理员角色调整属于已有校园资格的受控管理操作。
- 最后一个有效管理员不能被停用、撤销或降级。
- 答辩时不执行停用、撤销或角色调整，避免改变当前演示账号。

### 12.3 教学班列表 `/campus/classes`

**当前可见状态**

当前管理员账号会进入“管理员视图”。本地数据库没有教学班，因此页面会显示空状态。可以借此说明：代码功能已完成，但真实试点数据尚未初始化。

**角色差异**

- 教师：可创建教学班，填写班级名称、课程名称和学期；创建后自动成为首位教师。
- 学生：只看到自己加入的班级。
- 管理员：查看授权范围内的班级元数据，不在此创建教师课程。

### 12.4 教学班详情 `/campus/classes/:classId`

**教师视图**

- 编辑班级名称、课程名称和学期，或归档班级。
- 使用成员的校园身份编号加入学生。
- 新建教学任务草稿，填写标题、说明、学习目标、交付要求、截止时间和可选项目模板快照。

**学生视图**

- 查看班级和已发布任务。
- 在班级有效时主动退出；退出后立即失去班级和任务访问。

**管理员视图**

- 管理班级元数据与成员，可为班级安排教师。
- 页面明确不展示教学任务正文。

**讲解话术**

> 班级成员关系决定访问权，教师姓名字符串不能作为授权依据。跨班级不能凭 ID 读取，班级归档后保留只读数据，不级联删除个人学习记录。

### 12.5 教学任务详情 `/campus/assignments/:assignmentId`

**现场动作（准备教师账号和教学数据后）**

1. 编辑草稿中的标题、说明、学习目标、交付要求和截止时间。
2. 发布任务，观察状态从草稿变为已发布。
3. 展示发布后只允许延长截止时间。
4. 查看项目模板快照的采集时间。
5. 说明关闭和归档状态。

**讲解话术**

> 教学任务按“草稿—已发布—已关闭—已归档”流转。草稿对学生不可见；发布后冻结核心验收内容，只允许延长截止时间。引用项目模板时保存白名单快照，源项目后续修改不会静默改变已布置任务。

**演示边界**

- 当前没有教师、学生、班级和教学任务数据，所以本页不应宣称已完成真实课堂浏览器验收。
- P19 已完成提交版本、教师退回/通过、学生修改后重交和站内通知；当前本地库没有真实班级成果。

## 13. 老师可能会问的问题

### Q1：这个项目的 AI 具体在哪里？

AI 集中在可视化工作流和学习报告。工作流已有需求分析、技术栈分析、架构设计、解题提示、代码讲解和答案评审六类节点；后端通过统一 Provider 调用 DeepSeek，测试环境可使用 Fake Provider。系统保存请求、节点结果和运行历史。

### Q2：页面数据是真实的吗？

主要业务页面读取 MySQL。当前开发库有 74 个 Project 和 1 个有效校园成员；图表、项目进度、任务状态和学习分钟都由后端查询或聚合。首页专注计时器是页面辅助功能，不写入学习记录。

### Q3：为什么普通账号、教师和管理员要分开？

普通账号承载个人项目和学习数据；校园资格决定教学范围。一个账号当前只能有学生、教师或管理员中的一个固定校园角色，资源访问还需要班级成员关系。这样避免把“教师姓名”或前端按钮当成真正权限。

### Q4：管理员能查看学生的私人数据吗？

默认不能。管理员可管理账号、校园资格、一次性凭证、班级元数据和成员，但不自动获得私人项目、个人学习笔记、ProjectContext、AI 输入或教学任务正文的读取权。

### Q5：AI 会运行学生代码或自动判题吗？

不会。答案评审是静态分析，只提供问题、改进方向和建议学生自己运行的测试。当前系统没有在线 IDE、代码上传执行或自动判题能力。

### Q6：校园试点已经上线了吗？

没有。P17-P21 完成了身份、班级、成果反馈、AI 页面和社区治理的技术实现；真实教师、学生、课程、校方批准、AI 费用、部署和隐私政策仍待确认。当前适合展示毕业设计原型，不应表述为学校正式系统。

### Q7：下一步做什么？

下一阶段是 P22“AI 质量与成本控制”：把独立 Agent、Workflow、学习报告和测试入口纳入统一额度、并发和计量边界，并建立可复现的质量评测。平台预算、用户日额度、学校时区和真实评测费用仍待确认。

## 14. 技术架构讲解

### 14.1 前端

| 技术 | 用途 |
| --- | --- |
| Vue 3 + TypeScript | 单页面应用、组合式逻辑和类型约束 |
| Vite | 本地开发与生产构建 |
| Element Plus | 表单、提示、确认框和基础交互组件 |
| Vue Router + Pinia | 路由守卫、认证和领域状态 |
| Axios | API 请求、Token 注入和 401 处理 |
| Vue Flow | AI 工作流节点画布与连线 |
| ECharts | 学习和社区数据图表 |

### 14.2 后端与数据

| 技术 | 用途 |
| --- | --- |
| FastAPI + Pydantic | REST API、请求响应 Schema 和接口文档 |
| SQLAlchemy + PyMySQL | 数据访问、事务与 MySQL 驱动 |
| MySQL 8.0+ | 34 张表、81 个外键的主数据存储 |
| PyJWT + Argon2id | 会话令牌、版本失效和密码哈希 |
| HTTPX + DeepSeek Provider | AI 请求和统一 Provider 接口 |

后端保持单体分层：

```text
Vue 页面 → Axios API → FastAPI Router
→ Service 权限与状态 → Repository → SQLAlchemy Model → MySQL
                         ↘ Workflow Engine → Agent → DeepSeek
```

当前后端 OpenAPI 有 96 个路径、136 个操作。2026-09-25 的检查结果为后端 203 项测试通过、前端类型检查和生产构建通过、数据库 Models 与 34 张表和 81 个外键一致；Ruff、Mypy 和 Bandit 未安装，不能写成已通过。

## 15. 展示时应保持的口径

- 可以说“P00-P21 的代码和技术验证已完成”，不要说“真实校园试点已完成”。
- 可以说“支持 DeepSeek 和测试用 Fake Provider”，不要说“已接入所有主流模型”。
- 可以说“答案评审给出静态建议”，不要说“AI 自动判题通过”。
- 可以说“统计来自数据库”，但首页专注计时器不属于持久化学习证据。
- 可以说“教学班和任务接口、页面已实现”，同时说明当前没有真实教师、学生、班级和教学任务数据。
- Git 仓库保存代码和文档，不保存本地账号、密码、API Key、邀请凭证或 74 条业务数据。
