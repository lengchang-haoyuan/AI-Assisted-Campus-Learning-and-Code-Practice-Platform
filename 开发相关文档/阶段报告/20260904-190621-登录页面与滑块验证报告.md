## 2. 关键设计和调用链

页面保留 ScholarHub 的冷白、海沫绿和钴蓝配色，增加校园社区、项目实践和学习工作台三个可切换主题，复用已有图片。提供首屏渐入、主题滑动选中底片、图片过渡、滑块跟手形变和回弹、验证成功反馈。手机优先显示表单，支持减少动态效果。

调用链：`LoginView / SliderCaptcha → src/api/auth.ts → Axios → Auth Router → SliderCaptchaService → 原 AuthService → Repository → MySQL`。滑块逻辑不直接访问数据库，原密码哈希、JWT、身份校验及业务 API 不变。

新增公开 POST 接口 `/api/v1/auth/slider/challenge` 与 `/api/v1/auth/slider/verify`。挑战有效 120 秒，至少存续 0.5 秒；位置必须是整数 100。验证签发有效 60 秒的一次性随机凭证，成功或密码错误登录均消费凭证，前端失败后重新获取挑战。锁保护消费原子性，容量上限 2048，响应设置 `Cache-Control: no-store`，凭证不保存到日志、浏览器持久化存储或数据库。

兼容性：登录请求现在必须携带 `slider_token`，旧客户端省略该字段返回 422；伪造、过期或重放返回 400；容量不足返回 429。Swagger 演示及现有验证脚本已同步调整。注册接口、JWT 返回结构、已有用户和数据库无需迁移。

## 5. 手工验收步骤和实际结果

1. 打开登录页，切换三个主题：文字、图片和选中状态一致，有短时过渡，不影响填写表单。
2. 输入账号密码但不拖动：页面阻止登录并提示验证；部分拖动松开回到起点，拖到底后真实请求后端并显示验证通过。
3. 输入错误密码：通用 401 错误，不泄露账号是否存在；挑战自动刷新，重新拖动后能继续登录。真实测试账号成功登录并读取 `/users/me`。
4. 通过键盘显隐密码，用 End/Enter 完成验证：正常；服务端无效、过期和重放均被测试拒绝。
5. 桌面 1440px 与 320/390/768px 检查：无页面横向溢出，手机表单在前，完整插画在后。截图已核对。
6. 浏览器脚本模拟挑战网络失败，显示错误且刷新可恢复；推进浏览器时钟验证前端到期提醒。服务端到期由单元测试独立覆盖，不将前端计时结果当作服务端证据。
7. 减少动态效果模式关闭表单位移动画；两组浏览器回归未产生页面脚本错误。

## 6. 未执行检查、已知问题和边界

- 这是基础拖动验证，不是专业反机器人 CAPTCHA。位置由客户端报告，脚本可模拟完成流程；没有轨迹识别或成熟验证码供应商的反自动化能力，不能将其视为抗暴力破解保证。
- 挑战仅存于进程内，不支持多 worker/多实例共享；重启和开发热重载后会失效。公网生产部署需要独立评估成熟验证码、共享存储及限流，本次未扩大范围实现。
- 未对真实手机硬件触控做验收；本轮覆盖浏览器指针拖动、键盘及响应式视口。
- 未重复执行远程漏洞数据库审计：本次依赖及锁文件未变，P15 原有 npm advisory 超时问题没有新结论。`pip check` 仅证明依赖一致，不代表无漏洞。
- 原统计页 chunk-size 构建提示仍保留；本次未改统计模块，也未关闭警告。
