# 后端重启与 DeepSeek 鉴权报告

- 时间：2026-09-04 21:42:48 +08:00
- 需求：用户要求重启后端以重新检查 DeepSeek 接入。

## 结果与原因

第一次正常重启后，健康检查通过但鉴权仍为 401。进一步核对发现：继承的进程环境 DEEPSEEK_API_KEY 与 backend/.env 中的值不同，Pydantic 优先读取进程环境，因此此前的 401 不能证明用户填写的文件密钥无效。

在本次启动命令的临时 PowerShell 进程中移除 DEEPSEEK_API_KEY，再启动本项目后端。未修改用户级或系统级环境变量，也未修改 .env。

## 验证

- 采用同一清理后的启动环境加载配置，确认实际密钥与 .env 相同；未输出密钥。
- 官方 GET https://api.deepseek.com/models 返回 HTTP 200。
- 已配置模型出现在该 Key 可访问的模型列表中。
- 重启后的 /api/v1/health 返回 status=ok。
- 本次后端启动器 PID 18616，日志位于本机临时目录 ScholarHub-backend-20260904-214217。

## 范围与剩余限制

仅重启确认归属于本项目的后端，前端及 MySQL 保持运行。没有业务代码、依赖、数据库或全局配置变更。未执行生成请求，因此不宣称模型生成或工作流全链路已通过；工作流前端运行入口仍待接入。本次无代码变更，未重跑 Lint、构建与全量测试。

## 后续启动说明

从仍继承旧 DEEPSEEK_API_KEY 的终端启动可能再次覆盖 .env。再次启动时应在对应启动会话中去除该变量后启动，或另行授权调整持久环境；本次未修改持久环境变量。停止服务前先核对 PID 归属。
