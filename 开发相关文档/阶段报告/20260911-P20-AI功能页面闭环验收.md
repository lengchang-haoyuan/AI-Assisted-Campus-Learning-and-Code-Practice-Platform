## 2. 本阶段关键设计和调用链

项目详情通过 `/projects/:id/ai` 进入 AI 工作台。Context 链路为页面 → `src/api/workflowContext.ts` → 现有 `POST/GET/PUT /projects/{id}/context`。页面显示版本、更新时间、整体来源、字段来源、校验错误、项目字段漂移和受影响节点；保存发送 `expected_version`，409 时保留本地草稿并让用户主动载入最新版本。项目字段同步必须点击按钮，只提交后端报告的 stale 字段，且不会调用模型。

需求分析和开发 Prompt 链路为页面 → `src/api/agents.ts` → 现有 Agent API → Provider。按钮在请求期间禁用，输入按现有 Schema 约束整理；同步 HTTP 调用、超时、网络中断和“页面离开不等于服务端取消”均有明确说明。成功结果按判别类型显示，可复制纯文本或 JSON；用户可输入已有请求编号调用 `GET /agents/results/{request_id}` 刷新查询。页面不使用 `v-html`，模型内容不作为命令、权限或自动修改依据。

Workflow 编辑器取消了运行前自动创建或同步 Context 的前端行为。编辑器只读取 Context：缺失、字段漂移或读取失败时阻止运行并指向 AI 工作台；Context 可用时显示版本和受影响节点。工作流仍使用已有同步 `POST /workflows/{id}/run` 与有界运行记录查询，不伪装后台任务或取消成功。注册表当前真实支持需求分析、技术栈分析、架构设计和三个教学节点；质量检查继续显示为不可执行。

所有权仍由现有 ProjectContextService、AgentService 和 WorkflowService 在服务端按 Project owner 校验。校园教师或管理员角色没有获得私人 Context 或 AI 结果的额外权限。本阶段没有新增 Agent 类型、执行引擎、WebSocket、持久化格式或本地结果缓存。

## 3. 启动命令及必要环境变量
