## 2. 本阶段关键设计和调用链

- 新增 `TeachingClass`、`ClassMembership`、`TeachingAssignment` 三个独立实体，不复用或改写个人 `Course`、`DailyTask`、`Project`。
- 后端调用链保持 Router → Service → Repository → SQLAlchemy → MySQL；请求和响应使用独立 Pydantic Schema。
- 有效教师创建班级时原子创建首位教师成员。教师只能管理本人有效班级；管理员可查看班级元数据、管理成员和归档，但不能读取教学任务正文。
- 学生只能读取本人有效成员关系对应班级的非草稿任务。跨班级 ID 返回 404，停用校园身份返回 403。
- 成员唯一约束为 `(class_id, campus_membership_id)`；教师只能加入/移除学生，管理员可安排教师或学生，学生只能将自己的有效学生成员关系改为 `left`。
- 任务状态为 `draft → published → closed → archived`。发布后冻结标题、说明、学习目标和交付要求，只允许把截止时间向后延长；所有写操作使用 `expected_revision`。
- 项目模板只能引用教师本人 Project，保存白名单快照，不复制 `context_data`、私人笔记、AI 报告或仓库地址；源项目删除后快照仍保留。
- 列表统一有界分页。班级按创建时间和 ID 稳定倒序，学生任务按截止时间和 ID 稳定排序，空截止时间排在最后。
- 前端增加 `/campus/classes`、`/campus/classes/:classId`、`/campus/assignments/:assignmentId`，在同一 AppLayout 中按后端能力字段显示教师编辑、管理员管理或学生只读操作。

## 5. 手工验收步骤和实际结果

1. 使用真实 MySQL 创建隔离的两名教师、两名学生和一名管理员测试身份。
2. 教师 A/B 分别建班并加入不同学生；教师 A 读取 B 班、学生 B 读取 A 班均返回 404。
3. 教师 A 保存草稿，学生 A 列表为 0；发布后重新请求列表，学生 A 看到 1 条真实数据库任务。
4. 管理员读取任务正文返回 403；教师发布后改标题返回 409，延长截止时间成功。
5. 任务依次关闭、归档；学生退出后立即无法访问；B 班归档后仍有效的学生保留只读访问。
6. 隔离测试账号、资格、班级、成员和任务按外键顺序清理，最终临时用户剩余 0。
7. 浏览器访问受保护的 `/campus/classes`，未登录会话正确跳转 `/login?redirect=/campus/classes`；登录页正常渲染。未创建或保留真实/虚构校园账号，因此本轮没有通过浏览器登录后的角色页面视觉验收。
