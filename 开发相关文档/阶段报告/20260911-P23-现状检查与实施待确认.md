## 2. 本阶段关键设计和调用链

当前本地链路为 Vite `127.0.0.1:5173` → Uvicorn `127.0.0.1:8000` → MySQL。推荐试点链路为校内/VPN HTTPS → 校方 Nginx（Vue 静态产物和同源 `/api/v1`）→ 本机 Uvicorn 单 worker → 本机 MySQL 最小权限账号。部署保持单实例，不强制 Docker，也不引入 Redis、Celery、Kafka、微服务或新监控平台。

现有 `/api/v1/health` 只作存活检查；推荐保留兼容路径并新增数据库就绪检查。生产模式增加 Swagger 开关、可信 Host、HTTPS CORS 和启动前配置检查；前端生产 API 使用同源地址。数据库将运行、迁移和备份权限分离，当前 `root@localhost` 不能用于试点运行。

AI/Workflow 仍为同步请求。P22 的平台预算、用户日额度、未知用量和并发控制尚未实施，因此真实 AI 上线被阻塞。导出/删除推荐用最小 `privacy_requests` 请求记录、本人有界 JSON 导出和经审查的删除执行路径；具体表、API、留存期限与处理人需先确认。完整事实、选项、风险、恢复和禁止上线项见 [P23 实施方案](../开发规划/P23_校园试点上线保障与隐私实施方案.md)。

## 5. 手工验收步骤和实际结果

本轮只做技术现状核验，没有生产等价环境。实际确认当前三个本地端口监听、后端健康接口和 Swagger 可访问；检查构建产物发现未提供前端环境变量时会包含 `127.0.0.1:8000`，因此当前产物不能直接上线。

只读数据库检查确认 MySQL 8.0.46、`utf8mb4`、会话 UTC，应用连接身份为具全局管理权限的 `root@localhost`。真实库当前 2 个用户、1 个校园成员、0 个教学班/任务/提交，不能用当前数据推导班级容量。本轮没有导出数据库、创建恢复库、执行故障/压测、读取私人正文或调用真实 Provider。

根据 2026-02-10 的 [DeepSeek 官方隐私政策](https://cdn.deepseek.com/policies/zh-CN/deepseek-privacy-policy.html)，下游应用需要自行向终端用户披露处理规则；输入会被供应商处理，政策描述了模型优化退出、境内存储、必要期限和个人信息权利。当前无法从本地代码证明 Provider 账号的实际训练退出设置，未把供应商政策当作校方批准。
