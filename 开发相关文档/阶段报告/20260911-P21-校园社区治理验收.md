## 2. 本阶段关键设计和调用链

发布链路为项目所有者填写声明 → `POST /projects/{id}/publication-requests` → Service 校验所有权、有效校园身份、Project 更新时间和请求键 → 保存不可变 `CommunityPublicationVersion` → 管理员按 revision 通过或退回 → 通过后原子切换公开版本并写入通知和治理动作。教师只有在有效教师身份下才能申请 `practice_template`，且必须填写人工审阅说明。

社区列表、详情、标签、评论、点赞、收藏和举报统一要求有效校园身份。页面只读取已通过快照或迁移后的 `legacy_review_required` 快照；私人 Project 后续修改不会替换公开内容。历史 2 个公开项目被创建为“历史待审核”，保留 1 条评论、1 个点赞、1 个收藏和 5 条浏览记录，没有自动通过、下架或删除。

治理链路为有效成员举报精确项目版本或评论 → 管理员查看必要快照并接受/驳回 → 接受后下架项目或隐藏评论 → 受影响作者对具体动作申请一次复核 → 管理员接受时恢复原审核快照或评论。状态操作锁定目标并校验 revision；重复请求键返回同一结果，已处理案件再次处理返回 409。举报者身份、举报理由和内部备注不会返回给无关内容作者。

关键动作和通知在同一事务内落库。评论限制每人每小时 20 条，举报/复核限制每人 24 小时 10 次；服务器不访问仓库或来源链接。项目产生治理记录后禁止硬删除并提示归档，以保留公开快照、互动和审查证据。管理员处罚账号继续使用 P17 账号停用与审计入口。

## 3. 启动命令及必要环境变量

沿用现有 MySQL、`DATABASE_URL`、`JWT_SECRET` 和 CORS 配置，没有新增环境变量或依赖。已有数据库应先备份，再在 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m scripts.apply_p21_community_governance_migration
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

前端在 `frontend` 目录执行：

```powershell
pnpm dev -- --host 127.0.0.1
```

本机后端与前端已分别运行在 `http://127.0.0.1:8000` 和 `http://127.0.0.1:5173`，健康检查返回 `ok`。

## 5. 手工验收步骤和实际结果

真实 MySQL 验收使用虚构管理员、教师、学生、外部账号和项目，实际走通：发布申请 → 重复申请不新增版本 → 管理员通过 → 其他校园成员读取固定 V1 → 作者私下修改为 V2 后公开内容仍为 V1 → 举报成立并下架 → 直连详情不可读 → 作者只看到脱敏案件结果 → 复核成立后恢复 V1。评论同样完成发布、举报、隐藏、复核和恢复。无校园身份用户访问社区被拒绝，结束后虚构账号和所有关联数据均已删除。

## 6. 未执行或失败的检查、已知问题和剩余风险

- 浏览器脚本最初发现项目详情在 390px 下由图片和 grid 最小宽度引起溢出；已修正并复跑通过。登录后的浏览器验收使用 fake API，因为新浏览器会话无现成登录态且登录页有滑块；真实数据库业务链路由独立 Service 验收脚本覆盖。

- 历史内容仍等待管理员逐条审查；正式治理数据保留期限、版权判断、教师对模板的认可和校方社区政策均待确认。技术验收不代表公开互联网发布、真实课堂效果或校方批准。
