## 2. 方案取舍与实施前设计

| 方案 | 兼容性 | 失败率与用户体验 | 取舍 |
|---|---|---|---|
| A：服务端填入同次 Source 的事实 | 保留结果字段、API 与存储结构；新报告的六个事实值改由服务端确定 | 数字偏差不导致报告失败，不增加模型重试；分析仍来自模型 | **推荐并按本轮明确指令实施**。聚合来源已经提供事实，模型无须重新计算这些数值。 |
| B：逐项核对模型数字，偏差时保存 failed | 字段结构可不变，需要选择新的失败分类/提示 | 即使分析可用也拒绝整份报告，容易增加重试与生成失败 | 可行备选；本步不采用。 |

用户本轮明确要求执行 L3，并推荐服务端事实映射；选择 A 属于该授权内的最小修复。无需新增字段、数据库迁移、依赖或公共 API 路径，也不改变既有错误、安全和重试策略。缺少已确认专用隔离 MySQL 时按本轮明确约定交给 L4。

### 事实映射表

| 结果字段 | 来源 |
|---|---|
| `total_learning_minutes` | `source.learning.total_minutes` |
| `active_days` | `source.learning.active_days` |
| `task_completion_rate` | `source.tasks.completion_rate` |
| `project_average_progress` | `source.projects.average_progress` |
| `workflow_success_rate` | `source.workflows.success_rate` |
| `ai_request_count` | `source.ai_usage.request_count` |

1. Repository 只聚合一次，Service 校验并保留实际传给 Agent 的 Source；模型返回后不重新查询。
2. Agent 仍先校验模型原始输出的 JSON、字段、枚举、范围及敏感内容，非法输出继续走原 failed 路径；不能通过覆盖数字掩盖非法结构。
3. Service 在现有结果校验之后，将六个事实填入最终 payload，再计算现有 content_hash 并调用一次 `complete_generation`。AIResult 全部结果与 LearningReport 结构化事实使用同一最终 payload。
4. `performance_level`、`focus_areas`、`recommended_weekly_minutes` 和文字分析保持模型结果；不会据此声称文字事实已经逐项核验或消除了所有 AI 幻觉。
5. 列表、详情、生成响应和刷新仍读取已保存结果；历史报告不批量改写。本步不修改统计口径、P22、Provider 测试入口或 L4 工具。

## 5. 存量报告与 L4 交接

历史 completed 报告无法仅靠当前数据库重算还原当时的 Source；不在查询时静默替换历史数字。后续可单独确认：保留历史并限定事实可信度，或按新周期生成新报告；若确需补历史证据，应先确定当时聚合快照是否存在及明确重建范围。不得批量覆盖后称其为原生成事实。

专用隔离 MySQL 验收：用虚构数据与 Fake Provider，查询刷新后核对 AIResult、LearningReport、生成/列表/详情响应及页面事实卡片；覆盖错误数字、正确数字、零数据、边界、失败/取消/重试和所有权。本步未得到已确认专用隔离连接，当前未执行。L4 需要沿用“同次 Source 填六字段、保留模型判断/建议、先校验原始结构和敏感内容”的规则，不能重新查询当前数据库后冒充生成时快照。

本步验证只证明六个结构化事实的工程处理路径。文字摘要、收获或建议仍可能出现事实偏差，综合表现和每周学习分钟建议也不是数据库事实；没有执行收费模型质量评测，不能得出真实教学效果或“消除所有幻觉”的结论。
