## 1 当前持久化与接口子集

固定模板为 `python-learning-csv/1.0`，仅 `understand → implement`。每行 CSV 独立处理，不采用业务 ODS 的跨行主键去重规则。创建与选择模板不生成草案；指导结果是 `summary / guidance / checks`，模型成功后仍等待本人操作，不代表提交实现、执行代码或完成学习。

| 表 | 当前职责与约束 |
| --- | --- |
| `practice_sessions` | UUID；绑定本人、项目、模板、Context快照；保存步骤、八态status、revision及当前operation/request引用。`step_outputs`仅引用两步结果对应的 `ai_request_id`。 |
| `practice_attempts` | 同次迁移预留S08提交与静态评审；`UNIQUE(session_id, step_key, attempt_no)`及`UNIQUE(session_id, request_key)`。S07不创建尝试，不接受提交。 |
| `practice_events` | 真实动作与稳定event_key同事务保存；`UNIQUE(session_id, event_key)`；可空attempt引用使用复合FK保证属于同一session。 |

会话与尝试由项目／会话级联删除；owner引用为RESTRICT；AIRequest引用为SET NULL。复用既有 `ai_requests / ai_results` 保存请求、结构化结果、错误和用量，不修改旧WorkflowRun或已发布分析批次。

所有路径前缀为 `/api/v1`，身份来自现有认证依赖，不接受客户端指定owner。

| 端点 | S07实际行为 | 模型调用 |
| --- | --- | --- |
| `POST /projects/{project_id}/practice-sessions` | 创建固定模板本人会话，201；同键同载荷重放已有会话。 | 0 |
| `GET /projects/{project_id}/practice-sessions?offset=0&limit=20` | 本人项目历史，created_at/id倒序；limit为1–100。 | 0 |
| `GET /practice-sessions/{session_id}` | 查询当前步骤、绑定版本、结果引用、当前请求及可恢复状态。 | 0 |
| `POST /practice-sessions/{session_id}/actions` | 当前支持start、hint、explain、continue、confirm、cancel、resume；逐状态校验。 | 仅明确模型动作，最多1次；重放0次 |
| `POST /practice-sessions/{session_id}/attempts` | 对本人存在会话明确返回422，说明S07尚不支持提交／评审；不存在或非本人404。 | 0 |

非法结构／动作为422，未登录401，不存在／非本人404，版本、状态或同键不同载荷冲突409。`review`及任何非空 `attempt_id` 在S07返回422，不返回假成功。Provider与结构化结果失败沿用既有错误分类，另在持久化请求中保留错误。

## 2 状态与动作

| 当前状态／步骤 | 当前可用动作及后继 |
| --- | --- |
| `ready / understand` | start预约一次指导进入running；cancel进入cancelled；resume仅返回安全点。 |
| `running` | 有界模型完成：understand→waiting_confirmation，implement→waiting_submission；失败→failed。cancel立即取消；resume仅在recover_after到期后进行恢复处理。其他新模型动作拒绝。 |
| `waiting_confirmation / understand` | confirm表示本人确认理解，步骤改implement并进入waiting_submission；hint/explain预约一次指导后仍回人工等待；cancel可取消；resume不触发模型。 |
| `waiting_submission / implement` | hint/explain预约一次指导后回waiting_submission；cancel或resume为本地动作。提交／review尚未启用。 |
| `failed` | continue明确重试已绑定失败操作；cancel可取消；resume仅恢复查询安全点，仍为failed。 |
| `cancelled` | 仅resume：implement→waiting_submission；understand已有绑定结果→waiting_confirmation，否则→ready。不会自动重复旧模型调用。 |
| `waiting_revision`、`completed` | 八态已定义，但S07正常流程不产生这两态；不提前开放S08修订／完成动作。 |

成功本地动作使revision加1；一次正常模型动作在预约、结果绑定时分别加1。例如新会话为revision=1，start预约为2，指导成功绑定后为3；confirm后为4。失败、取消或恢复会影响实际版本，客户端必须以最近GET返回值为准。

`continue`是用户命令；Provider实际接收原操作的 `effective_action`（start、hint或explain）。服务端只允许重试当前绑定FAILED请求，保存 `retry_of.operation_id / ai_request_id / action`，保留原模板、步骤与Context，不把新continue当成任意新任务。每次新尝试使用新operation/request身份，Provider重试数固定0。

## 3 幂等、事务与快照

- request_key为规范化36字符UUID。创建事件key为 `<request_key>:create`，动作事件key为 `<request_key>:action`；相同键与载荷返回已有记录，不再次调用模型或增加成功事件。相同键不同载荷409。
- 动作重放先于expected_revision校验，响应 `replayed=true`：顶层是**当前会话状态**，`action_result`保留**原动作事件及其请求引用**。原事件的status/revision是动作当时记录，不保证等于当前顶层状态；其model_request通过原请求ID重新查询。
- 新动作必须匹配expected_revision。开始、取消、确认、恢复与事件在同一短事务内提交，回滚不留下成功事件。
- 锁序遵守 `Project → PracticeSession → PracticeAttempt → Event`，多行按ID；S07没有attempt写入。父ID提示在事务外只读定位，进入动作事务前结束旧干净快照；锁内重新核对本人、父项目及会话。创建重放定位在父锁后首次一致读，不反向获取Event锁。
- 预约事务保存operation_id、request、revision及running并提交；随后事务外等待Provider；结果事务重新核对owner、operation、revision、request和步骤。身份不匹配的迟到结果不绑定到会话。人工等待期间也无数据库事务。
- Repository拒绝接管已有new/dirty/deleted工作；查询禁autoflush。普通GET、刷新、confirm、cancel和resume不启动模型、Spark或业务抽取；GET不新增实践记录。

Context只在创建时绑定，检查expected_context_version及项目核心字段是否与Context一致。values白名单为 `project_name、language、framework、frontend、backend、database、difficulty、requirements、output_requirement、constraints`；保留版本／来源元数据，排除architecture、features、extensions正文值。后续项目Context变化不覆盖会话快照；新背景需新建会话。

## 4 中断、取消与迟到结果

请求预约时在 `AIRequest.request_metadata.recover_after` 保存“预约时间＋本次操作总超时＋10秒”。重启后的GET只显示持久状态，不自动修复或重发；running尚未到期时resume返回409。到期后本人显式resume使请求记为FAILED／`recovery_timeout`，会话转failed；随后如需新调用，再显式continue。该deadline由服务端判断，当前公开model_request摘要不直接返回recover_after。

running期间cancel会在同事务将当前请求记为FAILED／`cancelled`并保存会话取消事件。Provider可能已发生请求或费用；迟到成功仍可在原请求下保存AIResult、tokens、耗时及 `late_response=true` 作审计，但不把FAILED改为COMPLETED、不绑定输出，也不改变取消状态或新operation。

Provider等待期间若项目被删除，会话可随FK级联删除；完成处理仍终结原AIRequest，返回 `session_missing=true / detached=true`，不重建会话。外部请求中断后先GET核对原操作；不承诺Provider天然恰好一次，不静默补发。

## 5 事件与未来分析边界

| 当前事件 | 产生点 |
| --- | --- |
| `session_created` | 固定模板会话实际创建；辅助创建幂等。 |
| `session_started` | 合法start实际预约成功；与running提交同事务。 |
| `guidance_requested` | hint、explain或continue实际预约；辅助动作追踪与幂等。 |
| `step_confirmed` | 本人确认understand成功，confirmation_kind=understanding。 |
| `session_cancelled / session_resumed` | 合法取消／恢复实际提交。 |

action_payload由服务端固定构造：request（创建参数或action/expected_revision/attempt_id）、template_id、template_version、step_key、context_version、revision、operation_id、ai_request_id、status。事件不带代码、评语或原始Prompt正文。重复请求不增加事件；辅助 `session_created / guidance_requested` 不作为未来实践起始分母，未来起始事件只取真实 `session_started`，本阶段不新增事件分析指标或回填历史。

## 6 可复制请求体

以下只给不含凭证的HTTP body示例，不构成新增真实模型调用授权。project_id与session_id使用本人实际资源；示例revision仅对应无并发、无额外动作的成功顺序，实际须先GET。每个新动作使用新的UUID；网络中断要重放原动作时保留其原UUID、版本与完整载荷。

创建：`POST /api/v1/projects/{project_id}/practice-sessions`。

```json
{
  "template_id": "python-learning-csv",
  "template_version": "1.0",
  "expected_context_version": 1,
  "request_key": "10000000-0000-4000-8000-000000000001"
}
```

开始：`POST /api/v1/practice-sessions/{session_id}/actions`。

```json
{
  "action": "start",
  "expected_revision": 1,
  "request_key": "10000000-0000-4000-8000-000000000002"
}
```

start成功且GET显示waiting_confirmation、revision=3后，确认理解：

```json
{
  "action": "confirm",
  "expected_revision": 3,
  "request_key": "10000000-0000-4000-8000-000000000003"
}
```

此后implement等待提交，可明确请求提示：

```json
{
  "action": "hint",
  "expected_revision": 4,
  "request_key": "10000000-0000-4000-8000-000000000004"
}
```

失败支线：若首次start失败且GET为failed、revision=3，明确重试原操作：

```json
{
  "action": "continue",
  "expected_revision": 3,
  "request_key": "10000000-0000-4000-8000-000000000009"
}
```

cancel／resume使用同一actions端点，分别将action设为 `cancel`／`resume`，expected_revision改成当前GET版本，并各分配新request_key；两者均为0模型本地动作。不要把示例continue用于正常waiting状态。
