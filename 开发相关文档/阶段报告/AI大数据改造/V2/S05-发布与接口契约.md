## 2 离线准备与发布

[准备入口](../../../../analytics/prepare_publication.py) 仅离线读取 S04 完成 DWD：其 ADS 日 JSON 缺少 S01 已定的每日零值和来源计数，因此从已有 record_facts Parquet 投影补齐，并与 ADS 的每日记录/分钟/缺失数逐项核对。没有修改 S04 文件、重抽来源或新增指标。

在已具备 PySpark 的环境，从项目根运行下面命令；本轮 sidecar 已存在，禁止重复执行覆盖它们。

```powershell
python -m analytics.prepare_publication --job-id v2-controlled
python -m analytics.prepare_publication --job-id v1-boundary
```

结果位于 [主发布输入](S05-发布输入/v2-controlled/payload.json) 与 [边界发布输入](S05-发布输入/v1-boundary/payload.json)。[受控加载器](../../../../backend/app/services/analytics_artifacts.py) 只允许 S04 交接索引内这两个 job；验证 computed、质量对账、独立数据验收、版本、归属、窗口及 ADS 内容。未知 job、fixture、synthetic、路径穿越和未知规则均拒绝。API 不接受本地路径，也不导入该文件加载器。

以下命令在 backend 目录执行，使用已有本地连接凭证，不打印连接串；目标参数是必填的隔离库名称，不会修改 .env。

```powershell
.venv/Scripts/python.exe -B -X utf8 -m scripts.apply_s05_analytics_migration --database scholarhub_l4_s02_20261020
.venv/Scripts/python.exe -B -X utf8 -m scripts.publish_analytics --database scholarhub_l4_s02_20261020 --job-id v2-controlled
.venv/Scripts/python.exe -B -X utf8 -m scripts.publish_analytics --database scholarhub_l4_s02_20261020 --job-id v1-boundary
```

迁移两表都存在时只核对结构并返回 already_applied；只有一张存在时停止，不自行删除重建。发布 CLI 不启动 Spark、模型或 HTTP 服务。

发布状态为 `prepared → completed` 或 `prepared → failed`。先保存不可见的 prepared 头，再锁定该批次，校验输入、保存全部每日结果，并在同一短事务置 completed；失败回滚结果后安全记录 failed。接口始终只读 completed，因此失败新批次不会遮住旧成功批次。失败临时 daily 仅在这个未完成批次内清理重写；完成批次不可变。

同逻辑身份、同内容重放返回原 batch_id 和 replayed=true；异内容抛项目既有 ConflictError（409 语义），不更改完成头或结果。本阶段没有发布 POST，因此该冲突是离线服务/CLI 的实际异常，不称新增 HTTP 写接口返回。新规则或新 job 必须形成新的已验证产物与身份；旧完成批次不覆盖。

并发使用唯一约束与批次行锁。首次 INSERT 返回已知主键，避免默认 SQLAlchemy 过期对象刷新建立旧快照；重复 INSERT 后的身份查询也先结束事务，再取锁并读每日结果，避免 RR 下“头已完成、日表仍旧快照”的误判。两种发布先后顺序均有双连接实测。

## 3 两个只读 GET

[路由](../../../../backend/app/api/v1/analytics.py) → [Service](../../../../backend/app/services/analytics.py) → [Repository](../../../../backend/app/repositories/analytics.py) → Model，复用现有 CurrentUser、会话和错误结构，无管理员绕过。

### 本人完成批次列表

`GET /api/v1/offline-analytics/batches`

| 参数 | 约束 |
| --- | --- |
| dataset_kind | business（默认）或 controlled；synthetic 返回 422 |
| page / page_size | page≥1；size 默认20、范围1–50 |
| period_start / period_end | 可选但必须同时出现，1–90日；选择完全落入该查询周期的批次，不重算指标 |

按 source_cutoff DESC、batch_id DESC 排序，只返回认证本人 completed。拒绝 owner_user_id、user_id 及其他未知参数。响应为 items、total、page、page_size、empty_reason；items 中每项含批次、数据种类、窗口、时区、源截点、schema/metric/rule 版本、published_at。

| 空结果 | empty_reason |
| --- | --- |
| 本人指定种类尚无完成批次 | no_completed_batch |
| 有完成批次，但周期筛选未匹配 | no_matching_batch |
| 有匹配批次，但页码超出 | page_empty |
| 有返回项 | null |

三种空列表均 200，total 始终表示周期筛选后的总批次数。当前 controlled 有样例、business 没有，前端应明确选择数据种类，不能把默认 business 空列表解释为发布失败。

### 同批详情

`GET /api/v1/offline-analytics/batches/{batch_id}`

返回批次元信息、source 安全标识、records_summary、tasks_summary、topic_summary、quality、daily。详情是完整批次，不接受额外日期或分页参数；如需周期筛选，先调用列表选择一个完整批次，不能把部分 daily 和全周期专题混在一起。

未登录401；有效 UUID 对应不存在/非本人/未完成均404，包括空 completed 批次；非法 UUID 或参数422。空批次本人200，daily=[]，无任务比率 percent=null；记录数0与分钟缺失、NULL比率不是同一含义。管理员读取他人批次仍404。

比率保留 numerator、denominator、HALF_UP 六位 percent 字符串和 display；图表应使用精确数/分母。199/200=99.500000，不能用 display 判断全完成。取消任务仍在分母；记录时长 NULL 只计 missing_duration_count，不填成真实零。first_review_wait_* 来自受控 API 时间间隔，本轮不能解释为自然教学响应效率。

## 4 读取与故障边界

普通 GET 只走 ORM SELECT，不调用发布器、子进程、Spark 或 Provider。实际检查捕获 GET 期间 DML 为 []，Popen/AIClient.complete/publish 调用各0。旧 /statistics/today 仍从原业务即时聚合，语义与新离线 API 分开。

故障恢复使用相同已验证 job 再执行发布命令：失败批次在锁内重试，成功批次只重放。不要手工 UPDATE completed、DROP 表、清空整个库，或运行完整测试脚本重新灌数。当前 11 批次/15日行已经占用本轮授权上限 12/40 的一部分，证据脚本是历史操作记录，不能无条件重复执行。

成功、prepared、failed 的测试对象均保留；准确对象表见 [最终状态](S05-验证证据/final-state.json)。除了两个明确的 Spark 主/边界批次，其余都为权限/事务测试样例。仅以 [S06交接索引](S05-S06交接索引.json) 指定的两个批次进行正式接入，不能取“列表第一项”冒充真实 Spark 主样本。

本阶段没有启动或改配置让业务 Uvicorn 连接隔离库。验证使用实际 FastAPI ASGI 路由、真实认证和 MySQL；监听端口、浏览器、页面与缓存行为留 S06。
