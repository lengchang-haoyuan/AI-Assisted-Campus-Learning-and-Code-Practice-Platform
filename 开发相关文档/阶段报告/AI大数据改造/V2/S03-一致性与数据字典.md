# S03 一致性与数据字典

契约 V2-S01-r2；核心字段继承 [S01 数据字典](S01-分析固定样例与独立答案.json)，本轮副本见 [10 表字典](S03-样本/data-dictionary.json)。AI 辅助增量经用户单独批准，见 [S03 授权](S03-验证证据/authorization.json)。

## 来源、权限与时间

源为本机 `scholarhub_l4_s02_20261020`，真实 API 创建的虚构业务数据，标记 `controlled`。用户 3 的专题与用户 4 的 199/200 边界分别导出。教师成员行只为历史关系核验，不成为学生分析主体；不按当前成员是否 active 抹去历史反馈。导出主体须存在且 is_active，关联的项目、学习计划、课程按本人归属预检；辅助父表只输出核验计数。

主窗口为上海业务日 2026-10-19 至 2026-10-20，对应 UTC `[2026-10-18T16:00:00Z, 2026-10-20T16:00:00Z)`。其中时刻事实还受实际 source_cutoff 限制。scheduled_date 是 DATE，无时区转换。任务当前状态对应快照，不重建历史日终状态。

## 一致性读取顺序

1. 独立 Engine 的单个连接设置 REPEATABLE READ 与只读事务；检查来源及辅助表均为 InnoDB。
2. 执行 `START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY`。
3. 首读 `UTC_TIMESTAMP(6)` 为 source_cutoff，同时保存 CONNECTION_ID、isolation、read_only。它是观测截点，不是历史时间旅行查询。
4. 读取窗口内本人学习记录、任务；以 V1 在窗口内或窗口记录的来源 Feedback 为入口，读取提交头、完整版本链和反馈。
5. 补齐 Feedback 指向的记录、记录指向的任务、学生／教师成员、校园成员、班级、教学任务、本人项目。关联闭包可能跨窗口，后续指标必须重筛窗口。
6. 在同连接内预检未导出父表 users、learning_plans、courses 的存在与归属；只投影 metadata 的三个保留来源键。
7. 验证字段、类型、可空、枚举、外键、班级／教师／学生归属、版本序列及反馈时间关系后提交、关闭读取连接。
8. 事务释放后写 JSONL；在独立 `.incomplete/<id>-<attempt>` 下完成所有文件和 manifest，再同文件系统改名发布至 `snapshots/<id>`。

没有 JDBC 并行连接，没有最大 ID／created_at 增量水位。记录可修改、删除且无 updated_at，每次都重新读取完整窗口及闭包。source_cutoff、snapshot_started_at、snapshot_finished_at、file_generated_at 分开保存；合成数据的抽取时间为空，生成时间独立标记。

## 表与抽取字段

| 来源 | 选择与关系 |
| --- | --- |
| learning_records | 本人、occurred_at 窗口／cutoff，及 Feedback 指向的必要记录；不导出 title/content/完整 metadata |
| daily_tasks | 本人、原 scheduled_date 窗口，以及记录引用的必要任务；取消仍保留 |
| submissions | 本人 V1 在窗口内的固定群组，及记录来源所需父提交 |
| submission_versions | 所选提交的完整版本链；未来事件或状态矛盾阻止完成，不截断后宣称无修订 |
| feedback | 所选提交的完整反馈链；ACCEPT 与学习记录关系单独验证 |
| projects | 来源必要项目，核对 owner_id |
| teaching_classes / teaching_assignments | 提交关联的班级与教学任务，不按标题连接个人任务 |
| class_memberships / campus_memberships | 学生、教师关联键、角色、状态；不抽取姓名、邮箱、其他账户资料 |
| source_claim_projection | learning_record_id、source_claim、submission_id_claim、version_number_claim；只作未核实声明，不能代替 Feedback |
| ai_requests_aux | 本人 requested_at 窗口及 cutoff；独立 9 字段辅助白名单，不参与三类核心指标 |

source_claim 字符串最大 32；整数声明按类型与范围检查，非法值不复制任意 JSON 正文。实际教学来源需 ACCEPT Feedback、正确版本／班级／教师／学生和真实 learning_record_id 一起成立。Feedback.learning_record_id 为 NULL 时保留教师确认事实、记录关联缺失；不填时长。

9 字段辅助字典：

| 字段 | 类型 / 可空 |
| --- | --- |
| id / user_id | 正整数，不可空 |
| project_id | 正整数或 NULL |
| status | 当前 AIRequest 状态字符串，不可空 |
| requested_at | UTC Z 微秒，不可空 |
| finished_at | UTC Z 微秒或 NULL |
| prompt_tokens / completion_tokens / latency_ms | 非负整数或 NULL |

该辅助文件不导出 Token、密钥、提示词、input_summary、request_metadata、error_message 或 AIResult。Token 用量字段表示计数，不能视为实际模型质量。本轮只有 Fake 请求。

## manifest 与完成语义

含 dataset_id、snapshot_id、UUID batch_id、dataset_kind、主体覆盖、owner、schema/metric/rule 版本、窗口／时区、cutoff、抽取起止、过滤条件、同连接事务信息、辅助预检、各文件行数／字节及总输入字节。

`extraction_status=complete` 仅证明 ODS 抽取完成；`state=prepared` 表示尚待 S04 计算。故障目录只有失败记录、不得消费；重试使用新的 attempt 目录。完成目录禁止覆盖。相同逻辑内容的再次抽取仍产生新的 snapshot/batch。

## 小样本与规模来源边界

D00–D16 是 S01 固定虚构向量，保留输入、冻结预期和独立 Python 答案；故意冲突、非法来源等不进入真实库。15 个数据案例已核对，D13/D14 的发布／权限策略留待 S05。M01 增加三个主体的节奏、任务、修订／首次通过与空集合对照，含专题解释评分样例；AI 评分留待 S06。

规模集独立生成，100 合成主体各有 100 条唯一学习记录，另复制 200 条完全相同记录；20% 缺失、10% 已知零，其余 1–120 分钟。部分主体普通记录集中前 5 日，其余覆盖 30 日。教学状态按 30% 首次通过、30% 修订后通过、20% 退回、20% 待评生成，真实引用关系在文件内成立；这不证明真实学习行为或教学效果。
