## 2. 本阶段关键设计和调用链

- 校园资格独立于 User；未受邀的旧账号继续使用个人功能，普通注册不能提交角色。
- 邮箱邀请可在注册请求中原子完成 User、CampusMembership 和邀请消费；已有账号登录后在 `/campus/join` 兑换。请求中的角色不能覆盖邀请角色。
- Router 校验 DTO → CampusService 重新查当前账号和校园资格 → CampusRepository 在 MySQL 命名锁及事务内完成状态更新 → ORM 约束承担唯一性和外键底线。
- JWT 只保存 user_id 和 auth_version，不保存角色。受保护请求每次查数据库；加入校园、角色/资格/账号变化、改密、重置及撤销会话后旧令牌失效。
- 管理员页面只获取账号元数据、校园资格、邀请元数据和账号审计，不接入项目、学习笔记、Context 或 AI 输入查询。
- 首管理员只能通过指定现有有效 User ID 的维护命令初始化；无默认密码、无首个注册者自动升权，最后一个有效管理员不可停用、撤销或降级。
