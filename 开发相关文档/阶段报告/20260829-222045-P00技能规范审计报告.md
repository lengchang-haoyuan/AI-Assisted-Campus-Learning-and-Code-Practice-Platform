## 审查发现

### P2：复制 `.env` 后配置不会被应用自动加载

- `README.md:27-28` 要求复制 `.env.example` 后直接启动 Uvicorn，但命令未传入 `--env-file .env`。
- `backend/app/core/config.py:24-37` 只使用 `os.getenv`，没有加载 `.env` 文件。
- 影响：用户修改 `.env` 中的应用名、版本、CORS 或 API 前缀后，程序仍使用进程环境变量或默认值；文档描述与实际行为不一致。
- 建议：确认后选择 `pydantic-settings` 统一加载与校验，或至少让启动命令显式使用 `uvicorn --env-file .env`。

### P2：后端依赖没有可复现锁定

- `backend/requirements.txt:1-4` 只声明宽版本范围，没有锁定解析后的直接和传递依赖。
- 影响：不同时间或机器安装可能得到不同 FastAPI、Pydantic、SQLAlchemy、Starlette 等版本，测试结果和行为可能漂移。
- 建议：确认后选择项目统一的 Python 锁定流程，例如 `uv.lock`、Poetry 或 pip-tools；不要同时引入多套方案。

### P3：前端错误提示绕过了可配置 API 地址

- `frontend/src/api/client.ts:3-7` 允许通过 `VITE_API_BASE_URL` 配置地址。
- `frontend/src/stores/health.ts:28-30` 却固定提示“8000 端口”。
- 影响：部署到其他端口或域名时，错误提示会误导用户排查错误位置。
- 建议：改为不绑定端口的可操作提示，或从经过安全处理的配置中生成提示。
