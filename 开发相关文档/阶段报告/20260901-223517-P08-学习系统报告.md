# 任务完成报告：P08 学习系统

- 完成时间：2026-09-01 22:35:17 +08:00
- 任务范围：全栈
- 项目根目录：`ScholarHub/`

## 需求摘要

在 P07 个人工作台基础上实现 Course、LearningPlan、DailyTask、LearningRecord 的完整读写闭环。课程可被计划引用，计划具有日期范围和状态，任务可关联计划与项目并支持完成，记录保存学习时长、内容、发生时间、来源及关联资源。全部资源按当前用户隔离，只使用确定性业务逻辑，不接入 AI、Workflow 执行或学习报告。

## 修改内容

- 新增课程列表、创建、详情、更新和删除 API，支持有界分页和当前用户所有权隔离。
- 新增学习计划完整 CRUD，校验日期范围、关联项目/课程所有权和 `draft → active → completed/cancelled` 状态迁移。
- 新增每日任务完整 CRUD 与独立完成接口，校验计划日期、项目一致性、任务终态和完成幂等语义。
- 新增学习记录完整 CRUD，支持 `study/project/workflow/ai/course/task` 六类来源、1 到 1440 分钟时长和带时区时间。
- 任务完成、删除或迁移计划时在同一数据库事务中重算计划进度；P07 工作台旧完成入口也同步更新 P08 计划进度。
- 新增课程/计划总览、任务和记录三组前端页面，包含集中 Axios API、Pinia Store、显式 TypeScript DTO、表单校验、删除确认、重复提交保护及 Loading/空/错误/重试状态。
- 沿用轻盈实验室布告板基调，使用液态学习导航、数字滚动和 transform 进度动画，并保持窄屏与长文本布局稳定。

## 关键设计决定

- 决定：复用 P01 已有 `courses`、`learning_plans`、`daily_tasks`、`learning_records` 表和 ORM Models。
- 原因：现有字段与外键已覆盖 P08，避免 `schema.sql`、Models 和实际 MySQL 结构漂移。
- 决定：计划进度由所属任务完成比例计算，任务保存、删除和完成时在同一事务中刷新。
- 原因：避免任务返回成功但计划统计尚未更新的虚假一致性。
- 决定：完成和取消均为终态；新计划只允许草稿或进行中，计划进度未达到 100% 时不能标记完成。
- 原因：状态迁移明确、可测试，防止已完成资源被重新打开或绕过任务完成条件。
- 决定：任务关联计划后继承计划项目；任务型记录继承任务项目及计划课程，显式冲突时拒绝请求。
- 原因：保持课程、计划、任务、项目和记录之间的来源链一致，同时阻止跨用户资源拼接。
- 决定：数据库时间保持 UTC，API 接受并返回带时区 ISO 8601 时间，前端仅在展示和输入时转换本地时间。
- 原因：避免服务器时区和浏览器时区造成学习日期漂移。
- 用户确认：P08 提示词授权新增对应 API 与页面；本阶段没有触发新增依赖或数据库变更确认门槛。
