# P21 校园社区治理实施方案

状态：2026-09-11 用户已确认数据库、公共 API、历史内容和访问范围，技术实施与验收已完成。技术确认不等于教师确认或校方批准。

## 1. 实施前事实基线

- 社区当前以 `Project.is_published` 表示公开状态。项目拥有者调用 `POST /api/v1/projects/{id}/publish` 后会立即公开，撤回则直接清空公开状态；没有申请、审核、退回、下架或复核记录。
- 社区列表、详情、标签、评论、点赞、收藏和浏览量只要求账号已登录，没有校验 P17 的有效校园身份。评论只有作者软删除状态，管理员没有内容治理入口。
- P17 已有账号启停、校园资格停用和账号审计，P21 只调用现有账号管理流程，不创建第二套身份或处罚模型。管理员权限不扩展到私人 Project、Context、学习笔记、AI 输入或教学提交。
- P19 通知已支持本人分页、未读和已读，但 `assignment_id` 必填，通知类型只允许 `assignment_published`、`feedback_created`，不能直接承载社区治理事件。
- 2026-09-11 只读核对本地 MySQL：2 个有效账号，其中 1 个没有有效校园身份；56 个 Project 中 2 个当前公开，2 个公开项目属于同一位有效校园成员；现有 1 条可见评论、1 个点赞、1 个收藏、5 条浏览记录均关联当前公开内容。没有修改这些记录。
- 实施前 P16 的 D8 仍标为待确认，且明确禁止把历史公开内容自动视为已审核。用户在本轮确认 P21 技术方案后，待审核、通过、退回、撤回、下架与复核规则已按下文落库；教师和校方确认仍未取得。

## 2. 推荐状态与公开快照

每个进入社区治理的 Project 建立一个 `CommunityPublication`，每次申请建立不可覆盖的 `CommunityPublicationVersion`。社区只读取已批准的版本快照，不继续读取私人 Project 的实时字段。

状态使用 `legacy_review_required`、`pending_review`、`approved`、`returned`、`withdrawn`、`taken_down`。复核申请由治理案件单独记录，不伪造为作品审核状态。

| 场景 | 结果 |
| --- | --- |
| 首次申请 | 保存当前 Project 的公开字段快照和声明，进入 `pending_review`，尚无公开版本 |
| 审核通过 | 将待审版本设为公开版本，状态为 `approved`，同步 `Project.is_published=true` |
| 审核退回 | 保留版本和理由，状态为 `returned`；作者修改私人 Project 后用新请求键提交新版本 |
| 已公开作品更新 | 新版本进入 `pending_review`，旧的已通过快照继续公开；通过后原子切换公开版本，退回时旧快照不变 |
| 作者撤回 | 状态为 `withdrawn`，取消公开版本；评论、点赞、收藏和浏览记录保留但不再从社区入口访问 |
| 管理员下架 | 状态为 `taken_down`，取消公开版本并记录理由；作者可针对该动作提交一次复核 |
| 复核通过 | 恢复被下架的同一已审核快照；如作者改了内容，必须另交新版本审核 |
| 私人 Project 编辑 | 不改变已公开快照，不触发审核或通知，不公开 Context、笔记、AI 输入或教学信息 |

作品类型为 `work` 或 `practice_template`。模板只能由当前有效教师申请，除普通署名、来源/许可和 AI 辅助声明外，还必须填写人工审阅说明；页面明确显示“教师整理、平台已审核”，不标记为校方官方材料。

## 3. 最小数据变化

不新增依赖，不改写 P17-P19 已发布迁移。新增一份 P21 增量迁移并同步 Models、`schema.sql` 和数据库结构测试。

| 实体 | 最小职责与约束 |
| --- | --- |
| `community_publications` | `project_id` 唯一且可在撤回后置空、`owner_user_id`、作品类型、审核状态、公开/待审版本指针、`revision` 和 UTC 状态时间；公开/待审指针引用同一 publication 的版本；按状态、时间、ID 建有界队列索引 |
| `community_publication_versions` | `publication_id`、递增版本号、`request_key`、Project 公开字段快照、最多 5 个标签 JSON、署名、来源/许可、AI 辅助和模板人工审阅声明、提交时间；`(publication_id, version_number)` 与 `(publication_id, request_key)` 唯一，内容不可覆盖 |
| `community_governance_actions` | 记录申请、通过、退回、撤回、下架、恢复、隐藏/恢复评论等动作的主体、目标版本或评论、前后状态、理由和 UTC 时间；追加写入，不允许普通更新或删除 |
| `community_governance_cases` | 统一保存项目/评论举报和对下架动作的复核申请；包含发起人、精确目标、请求键、有界理由、状态 `pending/accepted/rejected`、处理人、处理理由、结果动作、`revision` 和 UTC 时间；每人对同一目标最多一条案件，同请求键幂等 |

现有表只做必要调整：

- `comments` 增加 `moderation_status visible/hidden`、`revision` 和治理时间；原 `is_deleted` 继续表示作者删除，列表同时排除作者已删和治理隐藏的评论。
- `notifications.assignment_id` 改为可空，增加可空的 `community_publication_id`、`community_case_id`，通知类型增加 `community_publication_changed`、`community_case_resolved`；每条通知必须且只允许一种业务目标。原教学通知字段和事件键保持兼容。
- `Project.is_published` 保留为“当前存在可见审核快照”的兼容字段。作品撤回或下架只改变可见状态，不删除评论、点赞、收藏、浏览或治理记录。现有社区计数继续统计保留记录；内容不可见时不提供详情和互动，恢复后沿用原累计计数。
- Project 一旦产生社区审查记录即禁止硬删除并返回 409，提示使用归档；这比设计草案中“撤回后允许硬删除并置空”更保守，可避免现有评论、互动和治理外键在删除时丢失证据。正式保留期限仍待校方确认，开发版不增加自动清理或批量删除。

## 4. 历史内容处理

推荐在迁移事务内为当时仍 `is_published=true` 且尚无治理记录的项目创建 `legacy_review_required` 记录和固定快照：

- 不自动标记通过、不自动下架、不删除历史评论或互动。
- 历史快照暂时只对有效校园成员可见，并显示“历史内容，待人工审核”；管理员待处理列表优先展示。
- 旧记录没有可证明的署名、许可或 AI 声明，数据库允许这些字段仅在历史版本为空，页面如实显示“未补充”。任何重新提交必须补齐声明。
- 管理员逐条通过后转为 `approved`；退回或下架后立即从社区入口隐藏。迁移执行前重新统计并备份；若数量或所有权与本方案记录明显变化，暂停重新说明。

备选方案是迁移后仅作者和管理员可见历史内容，直到逐条通过。它能更快收紧风险，但会把全部历史公开内容立即移出社区，兼容影响更大。禁止把历史项目批量自动通过。

## 5. 权限、并发和频率

- 社区浏览、搜索、标签、详情和全部互动统一要求 `User.is_active=true` 且 P17 `CampusMembership.status=active`。当前 1 个没有有效校园身份的有效账号会失去社区访问，但个人项目和学习数据保持原权限。
- 作者只能申请和管理本人 Project 的 publication；教师角色只额外允许申请实践模板；管理员只能通过治理专用响应查看公开快照、举报目标和内部理由。
- 管理决定、撤回、复核和评论隐藏均锁定目标并校验 `expected_revision`。重复同键同内容返回原结果，不同内容返回 409；已处理案件再次处理返回 409。
- 评论最长 2000 字并限制每个用户滚动 1 小时最多 20 条；举报/复核理由 3-500 字，每个用户滚动 24 小时最多 10 次。限制用数据库时间窗口和唯一约束实现，返回 429，不新增 Redis 或进程内锁。
- 项目 URL 和来源 URL 只作为声明展示；沿用 HTTPS、无凭据、无脚本协议的校验，服务器不抓取目标。模型或声明不会自动触发版权结论、审核决定或账号处罚。
- 举报成立时项目自动下架或评论自动隐藏；复核成立时只恢复原审核快照或原评论。账号停用需管理员到既有 P17 账号页另行确认并填写理由，结果写入现有 `account_audits`。

## 6. 公共 API 与前端

旧的直接发布接口停止即时公开；同仓前端在一次变更中切换到申请接口。读取社区项目的既有 URL 保留，但响应增加公开版本、治理标签和声明字段。

| API | 作用 |
| --- | --- |
| `GET /projects/{id}/publication` | 作者读取本人申请进度、版本和可执行动作 |
| `POST /projects/{id}/publication-requests` | 作者提交首版或更新版，携带请求键、Project 更新时间和声明 |
| `POST /community/publications/{id}/withdraw` | 作者按 revision 撤回，保留历史 |
| `GET /community/publications/mine` | 作者分页查看本人发布进度 |
| `GET /community/moderation/publications` | 管理员分页查看待审/历史待审内容 |
| `POST /community/moderation/publications/{id}/decisions` | 管理员按 revision 通过、退回或下架并填写理由 |
| `POST /community/reports` | 有效校园成员举报当前可见项目版本或评论，带请求键 |
| `GET /community/governance/cases` | 本人查看举报/复核结果；管理员按状态查看必要案件 |
| `POST /community/moderation/actions/{id}/appeals` | 受影响作者对下架或隐藏动作提交一次复核 |
| `POST /community/moderation/cases/{id}/decisions` | 管理员按 revision 接受或驳回举报/复核并记录理由 |

现有 `POST /projects/{id}/publish` 不再保留“绕过审核立即公开”的能力，改为返回 409 和新入口提示一个发布周期后再移除；现有 `DELETE /projects/{id}/publish` 映射为作者撤回以减少旧客户端误操作。无权目标统一 404，校园资格不足返回 403，状态/版本冲突返回 409，频率限制返回 429。

前端复用现有社区、Project 详情、通知和校园管理导航：

- Project 详情把“确认发布”改为申请表单，展示声明、版本、审核状态、理由和撤回/重提动作。
- 社区列表/详情读取审核快照，显示作品/模板、历史待审和声明；项目及评论提供举报入口。
- 新增一个复用页面 `/community/governance`，普通成员查看自己的发布、举报和复核；管理员在同页增加待审核、待处理和治理记录标签。`/campus/admin/accounts` 只增加跳转，不扩成第二个治理实现。
- 通知页兼容教学和治理通知，按通知目标进入发布进度或案件详情。所有表单防重复提交，具备加载、空、失败、权限变化、分页、键盘、窄屏和减少动态效果状态。

## 7. 实施、验证与恢复

确认后按 Model/迁移 → Repository/Service → Schema/API → 前端 → 测试与真实 MySQL 隔离验收实施。迁移前在工作区外备份；迁移只追加，出现问题优先前向修复。应用代码回退时保留治理表和历史快照，不能用删表恢复；恢复数据库备份涉及丢失恢复点后的数据，须另行确认。

验收覆盖历史兼容、申请/更新快照、审核/退回/撤回/下架/恢复、项目和评论举报、复核、通知一致性、重复/并发请求、直连不可见详情、收藏/互动限制、账号/校园资格变化、模板教师授权和 Project 删除边界。只使用隔离虚构数据，不批量处理真实内容。

确认范围仅是上述技术方案。教师认可、校方批准、正式保留期限和真实版权判断继续标记待确认。
