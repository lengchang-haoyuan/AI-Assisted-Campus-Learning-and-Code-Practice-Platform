# P22 AI 质量与成本控制实施方案

状态：2026-09-11 完成现状核对与最小方案。数据库、公共 API、AI 调用策略和安全默认值等待用户确认；运行时代码和数据库尚未修改。技术确认不等于费用批准、教师评审或校方批准。

## 1. 实施前事实

### 1.1 实际 AI 入口

| 入口 | 当前限制 | 当前计量与缺口 |
| --- | --- | --- |
| `POST /api/v1/ai/test` | 登录即可调用；提示词最多 4000 字符、输出最多 2048 token；可指定模型 | 不创建 `AIRequest`，调用和 token 完全不落库，是当前最直接的额度绕过入口 |
| 三个独立 Agent | 单次输出最多 3000 token；单回合；总超时 30 秒；AIClient 最多重试 1 次 | 调用前创建 `AIRequest`；成功保存输入/输出 token，失败通常为空；没有请求键、个人日额度或跨入口并发限制 |
| Workflow | 最多 12 节点/12 回合、单节点最多 3000 输出 token、单次 Workflow 最多 9000 输出 token、总超时 90 秒；同一 Workflow 只允许一个活动运行 | 每个节点创建 `AIRequest`；单次预算只累计 completion token，缺失时按节点上限计算；换 Workflow 或改用 Agent/报告可继续调用，不是用户或平台预算 |
| AI 学习报告 | 单周期最多 90 天；同一周期完成后不重复生成；运行记录 10 分钟后可恢复 | 创建 `AIRequest`；失败、超时和恢复记录没有可核对用量；没有跨周期、跨入口额度或并发限制 |

所有生产入口最终经过 `AIClient → DeepSeekProvider`，但每个 HTTP 请求会创建独立 Client，没有全局或单用户并发控制。AIClient 日志包含一次应用调用内的尝试次数，持久化记录不保存尝试次数；成功响应只保存最终返回的 usage。底层首次尝试可能已经产生费用后再重试，当前数据库无法表示这种不确定用量。

真实 MySQL 只读聚合显示 22 条 `deepseek/deepseek-v4-flash` 标记的 `AIRequest`：21 条完成且都有 token，合计 24996 输入 token、8123 输出 token；1 条失败且 usage 为空。`/ai/test` 从未计入这些数字，因此 33119 个已知 token 不能视为供应商账单或历史总费用。当前数据库有 2 个用户、1 个有效校园成员、0 个教学班，没有事实支持现在增加班级额度。

当前本地已配置 Provider 凭据，只说明技术上可能发起真实调用。P16 D7 的费用承担者、额度数值、学校时区、真实学生数据外发和教师 AI 教学用法仍未确认；本次检查没有调用 Provider，也没有产生新的模型用量。

### 1.2 质量与报告现状

- Agent 和学习报告已有输入长度、提示注入隔离、敏感内容拒绝和结构化结果 Schema；这些是格式与安全边界，不是代表性质量评测。
- 仓库没有需求分析、开发 Prompt、技术建议和学习报告的统一评测样例、评分量表或人工评审记录。
- 学习报告输入只含数据库聚合指标，但 `structured_data` 仍由模型返回，页面把 `performance_level` 显示为“综合表现”。当前没有持久化生成当时的事实快照，也没有独立展示“数据库事实、学生自述、AI 建议”；历史刷新时无法证明模型复述的数字等于生成时数据库事实。

## 2. 需要确认的取舍

| 决策 | 选项 | 推荐意见 |
| --- | --- | --- |
| 启用策略 | A. 新配置缺失时关闭全部新模型调用；B. 缺失配置时继续无限调用；C. 只观察不拦截 | **推荐 A**。`.env.example` 使用 `AI_USAGE_CONTROL_ENABLED=false`；只有明确配置预算后才能开启。B/C 不能满足成本准入，A 会使升级后未配置环境的新 AI 调用返回 503，属于需确认的兼容变化 |
| 计量单位 | A. token 额度和已知/未知用量分开；B. 按人民币估算 | **推荐 A**。P22 不掌握供应商账单、价格版本和付款方，不能可靠展示金额。UI 明确“额度不是账单”，只展示 Provider 返回的实际 token 与保守预留 |
| 配额层级 | A. 平台试点总额 + 用户每日额度；B. 同时加入班级额度 | **推荐 A**。当前 0 个班级，而且私人 Project/Agent 无法唯一归属班级；现在加入班级额度会制造错误归属。班级额度在真实班级和归属规则确认后单独设计 |
| `/ai/test` 权限 | A. 仅有效管理员、仅配置模型、仍计量；B. 维持所有登录用户和任意合法模型名 | **推荐 A**。该接口是通用 Provider 诊断入口，不是学生学习功能。此项会让普通用户原调用返回 403，并拒绝非配置模型，属于明确的公共 API 行为变化 |
| 学习报告事实 | A. 新增生成时事实快照并分栏展示；B. 只改前端标题 | **推荐 A**。只改标题无法证明模型复述数字的来源。历史报告不伪造回填，事实快照为空时明确标记 |

推荐技术默认：平台最大同时调用 2 个、单用户 1 个、预留 10 分钟后仍未结算则转为“用量未知”并继续占用额度。用户每日额度在学校时区 00:00 重置；当前原型推荐 `Asia/Shanghai`，仍需用户确认。平台总预算使用持久化 `budget_key` 分期，改 key 才开启新一期，不因服务重启清零。

用户每日额度和平台试点总额度不建议由开发者猜测。确认实施时可以先保留真实调用关闭，仅用 fake Provider 验收；等费用承担者、总 token 上限和个人日 token 上限明确后再写本地环境配置。

## 3. 最小数据变化

不新增第三方依赖，不改写 P11-P21 已发布迁移。确认后新增一份 P22 增量迁移，并同步 SQLAlchemy Models、`schema.sql` 和结构测试。

| 实体或字段 | 最小职责 |
| --- | --- |
| `ai_usage_buckets` | 保存 `platform_total` 或 `user_daily` 范围、不可变周期起止 UTC、配置额度、已预留、已结算、未知用量、revision 和时间；平台范围使用配置 `budget_key`，用户范围引用 User；唯一约束保证一个范围和周期只有一个桶 |
| `ai_usage_records` | 每次应用级模型调用一条记录：用户、可空 `ai_request_id`、入口、唯一操作键、Provider/模型、状态 `reserved/settled/unknown/released`、预留单位、实际输入/输出/总 token、尝试次数、失败类别、两个 bucket 关联和 UTC 时间；不保存 Prompt、模型原文、凭据或认证头 |
| `learning_reports.source_snapshot` | 可空 JSON，保存新报告生成时通过 Pydantic 校验的聚合事实；历史报告保持空，不按当前数据库倒推过去事实 |

不为评测创建数据库表，不创建班级配额表，不修改 `AIResult` 的既有结构。现有 22 条 `AIRequest` 不回填为 P22 计量记录，也不从新额度扣减；管理页明确显示“P22 启用后的受控用量”，历史已知值只写入本次技术报告。

## 4. 预留、调用和核销

每个生产调用必须显式携带 `user_id`、入口和操作关联；测试可注入 no-op 计量器，不能让新生产入口绕过计量 Client。

```text
边界校验与授权
  → 生成/读取 AIRequest（/ai/test 无 AIRequest）
  → 事务锁定平台桶与用户日桶
  → 恢复过期 reserved 为 unknown
  → 检查平台开关、剩余额度、用户/平台并发
  → 创建 usage record 并增加两个桶的 reserved
  → 提交事务
  → 调用 Provider（事务和行锁已经释放）
  → 新事务结算 settled / unknown / released
```

预留值使用“输入消息 UTF-8 字节数 + 请求 max_tokens + 固定消息开销”的保守 token 额度估计，只用于入场控制，不冒充供应商 token。首次尝试成功且 Provider 返回完整 usage 时，按 `total_tokens` 结算并释放差额。Provider 成功但 usage 缺失、发生底层重试、网络/超时/取消、认证失败或响应格式异常时，保留完整预留为 `unknown`；配置缺失或调用前验证失败确认没有发出 HTTP 时释放预留。

如果 Provider 报告的实际 token 大于预留，按实际值结算、记录异常并阻止后续新调用；应用额度可避免普通并发超额，但不能保证供应商账单恰好等于本地计量。过期预留只在下一次额度操作或查询时转为 unknown，不自动退款；平台负责人可据 Provider 账单人工核对，P22 不提供可随意改账的管理 API。

独立 Agent、Workflow 每个节点、学习报告和 `/ai/test` 都通过同一计量边界。Workflow 保留现有单次 9000 completion token 预算；它是运行内第二道上限，不替代平台或用户额度。一个应用操作可关联多次底层尝试，但 P22 不承诺外部模型只收到一次请求。

## 5. 公共 API 与错误语义

建议新增：

| API | 权限与响应 |
| --- | --- |
| `GET /api/v1/ai/usage/me` | 当前用户查看平台开关、本人日周期、额度、reserved/settled/unknown、剩余量、重置时间和当前并发；不返回其他用户 |
| `GET /api/v1/ai/usage/records` | 本人有界分页查看入口、模型、状态、已知 token、预留、失败类别和时间；不返回 Prompt、结果正文或内部错误 |
| `GET /api/v1/ai/usage/admin/summary` | 仅有效管理员；返回平台预算、聚合入口/状态/模型计数、已知/未知用量和活跃用户数量，不返回个人学习正文、Prompt、Context 或结果 |

既有成功响应保持不变。额度耗尽与并发达到上限返回 429，提供稳定错误码和可重试时间；平台开关关闭、预算期未配置或已结束返回 503；无权访问管理员统计或普通用户调用 `/ai/test` 返回 403。前端只使用服务端响应，不用浏览器时区、用户 ID 或本地计数决定额度。

## 6. 前端最小变化

- 新增 `/ai/usage` 共用页面：普通用户看本人额度和记录；管理员额外看匿名平台汇总。页面有加载、空、关闭、额度不足、未知用量、失败和重试状态。
- P20 AI 工作台、Workflow 运行区和学习报告区复用一个小型额度摘要，调用完成或被拒绝后刷新；按钮防重复提交仍只负责交互，服务端额度和并发是最终规则。
- 学习报告改为“数据库事实 / 学生自述 / AI 建议”三块。新报告的数据库事实读取 `source_snapshot`；当前没有学生自述字段时显示“本报告未收集学生自述”；`performance_level` 改标为“AI 建议阶段”，不得显示为成绩或已确认能力结论。
- 所有 token 与预留使用整数并标出“本地额度计量，不等于供应商账单”；不展示人民币估算或虚构剩余额度。

## 7. 质量评测

新增版本化、脱敏的固定样例，覆盖需求分析、开发 Prompt、技术建议和学习报告。样例只含公开技术题目和虚构聚合指标，记录来源类型、期望 Schema、必须引用的事实、禁止结论、提示注入和敏感文本边界。

自动化使用 fake Provider 分别返回正确结构、错误技术建议、事实不一致、解析失败、模型拒绝、敏感内容和超时结果，验证：

- 无效结果不会写成成功，也不会修改 Project、Context、教学提交、成绩或权限；
- 学习报告的数据库事实由服务端事实快照决定，模型不能改写；
- 额度关闭、耗尽和并发拒绝在 Provider 调用前发生；
- 重复核销、超时、重试、usage 缺失和服务重启后的过期预留都有唯一记录和可复查状态。

技术评测结果输出脱敏 JSON 证据和阶段报告。另建人工教学评审清单，评审人、日期和结论初始为空并标记“待完成”；不创建教师通过记录。真实 DeepSeek 评测不在本次默认验收中，只有用户另行明确最大调用次数与费用上限后执行。

## 8. 迁移、兼容和恢复

确认后先在临时克隆库演练 P22 迁移，再在工作区外备份正式开发库并应用。迁移只新增两张表和一个可空列，不清空或重算历史 `AIRequest`/报告。应用代码回退时先通过环境变量关闭新模型调用，保留计量表和事实快照，使用前向修复；不能删除计量记录或把 unknown 改成零来恢复额度。

`/ai/test` 收紧、既有 AI 入口新增 429/503，以及升级后默认关闭模型调用均是有意兼容变化。原 Agent、Workflow 和学习报告成功响应、结果查询与已保存历史保持兼容；历史报告只缺少事实快照提示，不重写模型结果。

## 9. 实施与验收顺序

确认后按 Config/Error → Model/迁移 → Usage Repository/Service → AIClient 与四类入口 → 额度 API → 学习报告事实边界 → 前端 → fake 质量/并发测试 → 临时库与正式库迁移 → 浏览器验收实施。

进入实施前需确认：

- [ ] 采用缺少额度配置时关闭模型调用，且当前本地 `.env` 不由本阶段自动填写额度。
- [ ] 采用 token 额度而非人民币估算；认可预留、已知结算和 unknown 不自动退款的语义。
- [ ] 本阶段只做平台总额和用户每日额度，不做班级额度。
- [ ] `/ai/test` 改为有效管理员专用，并只允许当前配置模型。
- [ ] 学习报告新增事实快照和三类信息展示，历史报告不回填。
- [ ] 确认学校日界线；推荐 `Asia/Shanghai`。
- [ ] 后续启用真实调用前，由费用承担者提供平台总 token 上限、用户每日 token 上限和平台 `budget_key`。

等待确认期间保持现有服务和数据库不变，不调用真实 Provider，不执行迁移，也不创建提交。
