# P22 AI 质量与成本控制：可直接投喂给 AI 的提示词

基于现有 Provider、Agent、Workflow Engine、AIRequest/AIResult、学习报告与 P20 页面，为校园试点建立可验证的 AI 使用限制和质量评估。本阶段不做付费充值、自动扣费、模型训练或新 Agent 平台。

## 先检查现状

读取工作区规则、前后端目录职责、AI 提示词 README、P16 确认方案及最新报告。检查所有实际 AI 调用入口、单次 token/回合/超时限制、重试、日志和持久化；不要认为已有单次 Workflow 预算等于用户或平台总预算。

沿用现有 FastAPI 分层、MySQL、Provider/AIClient 和前端 Vue 3 + TypeScript + Element Plus。不默认引入 Redis、Celery、向量数据库或 LangChain；新增依赖、公共 API、数据库或安全策略变更先说明并等待确认。

## 本阶段目标

- 实现已确认的用户每日使用额度与平台总预算，必要时按班级分配额度；支持用户查询本人剩余额度及管理员查看必要的匿名汇总。
- 对独立 Agent、Workflow、学习报告及已有 AI 测试接口统一执行限制，不能通过换入口或重复请求绕过；平台总开关关闭时不得继续发起新模型请求。
- 限制并发请求和单用户重复运行，超过限额返回明确可恢复错误；限额由服务端配置与计量，不能信任客户端提供的使用量、用户 ID 或时区。
- 建立代表性评测样例与评审记录，检查需求分析、开发 Prompt、技术建议和学习报告的正确性、可操作性、教学价值及安全边界。
- 页面展示调用状态、额度不足和已知用量；学习报告区分数据库事实、学生自述和模型建议，未知事实不补写，不直接生成成绩或能力结论。

## 计量与一致性

1. 先明确计量单位、统计周期、学校时区、输入/输出 token、底层重试和缺失 usage 的处理方式。费用若采用估算必须标注，不能将模型 token 记录等同供应商账单。
2. 使用数据库事务、唯一约束或现有版本控制预留/核销额度，防止并发超额和重复扣减；不得在数据库事务或行锁内等待模型网络调用。
3. 供应商超时或断线可能已经产生费用，不能无条件把额度全部退回后自动重试。为用量未知、预留未结算和服务重启定义有界处理与人工核对策略。
4. 同一请求、运行或节点重试应可关联；沿用有界重试和总预算，不在本阶段保证无法证明的“外部模型恰好调用一次”。
5. 仅保存使用量、模型、状态、耗时、失败类别及必要关联 ID，不保存密钥、认证头或完整敏感 Prompt。管理员统计不泄露个人学习正文。

## 质量与安全评估

- fake Provider 覆盖结构成功、解析失败、拒绝、超时、限流、预算耗尽、并发竞争、重复核销和重启后的未结算状态；断言被拒绝的请求没有调用 Provider。
- 使用不含真实个人信息的样例检验课程约束、事实一致性、错误技术建议、提示注入和敏感信息边界；模型不能扩大权限、执行 shell/SQL 或直接修改教学结论。
- 明确评测标准和样例来源。教师未实际审阅时标为“技术评测完成，教学评审待完成”，不得伪造教师通过记录。
- 真实模型评测只在用户明确授权的次数与费用上限内运行；报告提供模型、评测时间、失败样例和已知局限，不以一个成功案例宣布可靠。

## 前端与验收

遵循 `$frontend-backend-code-standards`，API 集中、类型明确，沿用现有视觉及可访问交互，不展示虚构额度或成本。用户看本人额度，管理员看授权统计；处理加载、空、错误和重试。

验收：设置小额度 → 成功调用 → 用量更新 → 并发触及限额 → 后续调用被拒绝 → 查询计量记录；用户不能通过其他 AI 入口绕过。平台总预算、日界线、失败和未知用量策略均有测试证据，原 Agent/Engine/报告测试继续通过。
