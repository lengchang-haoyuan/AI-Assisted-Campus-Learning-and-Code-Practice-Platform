# R5 论文定稿与答辩：可直接投喂给 AI 的提示词

现在执行 ScholarHub [毕业设计整改方案](../开发规划/20260927-毕业设计整改方案.md)中的 **R5**。先读取 R0 范围页、R1 论文证据骨架、R2 演示材料、R3A/R3B 实验结果与 R4 最终验证报告。若学院任务书或论文/PPT 模板可用，以其格式为准；缺失时先产出明确标为草稿的正文和幻灯片结构，列出需用户提供的材料，不虚构学校要求。

## 论文成稿

1. 按“绪论与相关工作 → 需求分析 → 系统设计 → 关键实现 → 测试与实验 → 总结与局限”组织内容。正文聚焦 R0 确定的三个关键技术点，不按 30 个页面或 P00–P24 时间流水账写作。
2. 对每个事实、图、表和截图注明来源与口径；技术测试、虚构数据实验、真实 Provider 输出、人工评价分别说明。参考文献逐条核对，不编造论文、链接、页码或引用内容。
3. 明确讨论样本规模、模型不确定性、统计口径、未获教师评阅、未做真实班级试点及生产部署边界；未做的实验不能用计划代替结果。
4. 核对整改方案 C1–C4 的最终状态：未解决的学习报告数字一致性不得写为事实正确；技术栈百分比口径未核准时只引用数量；旧全链路脚本失败和 AI 测试入口边界如实写入局限。
5. 若学校要求可编辑 Word/PDF，使用已提供模板并做渲染与逐页检查；没有模板时先提供可审阅的 Markdown 草稿，不擅自称其符合学校最终格式。

## 答辩准备

1. 准备一份约 10–12 分钟的 PPT 或幻灯片草稿：问题与目标、设计、关键实现、实验结果、演示、局限。配一条主线演示脚本和离线备用截图。
2. 准备针对数据指标口径、AI 幻觉与质量、权限隔离、技术选型、个人贡献、未进行真实试点等追问的短答案；回答以当前证据为准。
3. 提供两次计时排练的记录表和检查清单。只有用户或实际参与者完成排练并提供结果后，才能填写“已完成两次排练”；AI 估算朗读时间不算真人排练。
4. 检查论文、PPT、截图、演示库均不包含密码、密钥、真实学生信息或不应公开的模型输入。

## 交付与验收

- 论文草稿或符合已提供学校模板的最终稿、PPT/幻灯片、演示脚本、备用截图索引、追问卡片和排练记录表放在 `开发相关文档/答辩材料/` 或学校指定位置。
- 论文每个主要结论可回指 R1 矩阵、R2 演示、R3 实验或 R4 验证；无法支撑的说法改为局限或删除。
- 按现有目录约定追加中文时间索引操作记录和本步报告。最终中文汇报文件、版式检查、证据对应、尚待学校/导师确认项和真实排练状态；不得把文档生成、模拟演讲或模板草稿写成正式答辩通过。不要提交或推送 Git。
