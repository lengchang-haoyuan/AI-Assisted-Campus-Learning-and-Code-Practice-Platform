# L1 终态学习计划与任务约束：可直接投喂给 AI

现在执行 ScholarHub [闭环缺口清单](../开发规划/20260927-项目逻辑与代码闭环缺口清单.md)中的 **L1**。目标是让学习计划终态、任务集合与计划进度一致，完成必要的最小修复和回归。本步不自动新增“重新打开计划”的产品功能。

1. 追踪 create_task、update_task、complete_task、delete_task 和工作台完成任务入口；区分任务状态与计划状态，核对实际进度公式。
2. 最小复现：本人计划的已有任务全部完成，计划标记 completed，之后新建待办任务关联该计划；另测 cancelled 计划和把已有任务改挂到终态计划。
3. 先用现有测试边界复现；Mock 允许进入保存调用只证明 Service 路径，不能写成真实数据库已经产生矛盾。

## 明确最小规则

输出一张“计划状态 × 操作”规则表，至少列出新建、改挂入、改挂出、删除、首次完成、重复完成和只改标题等操作。推荐终态计划不能通过任务操作隐式改变其任务集合、完成数量或进度；保留合法历史查询与幂等返回。只增加维持该不变量所必需的限制，不把终态理解成所有字段都禁止编辑。

- 核对已有文档或本任务中是否已有明确业务决策；已有授权则继续。
- 如冻结范围需要新的产品决策，先提交最小复现、影响和推荐规则，按共同约束取得必要确认后实施。
- 不为了关闭缺口自动把 completed/cancelled 改回 active，也不自动修改或删除存量任务。

## 实施范围

- 规则由服务端独立执行，必要时复用小范围的现有领域校验；学习与工作台入口应一致。
- 前端创建/改挂选择项与后端规则一致；编辑历史任务时应仍显示当前关联，避免隐藏选项造成误清空。
- 保持 API 结构和数据库不变；如实际证据要求改变，再按确认流程处理。
- 对新增任务、改挂或删除等能影响进度的可到达路径做必要检查；避免只堵一个入口后仍可从另一路径破坏同一不变量。

## 验收

- completed/cancelled 的非法关联或变更返回项目已有的明确冲突语义；失败前后计划及任务不变。
- draft/active 中合法创建、移动及完成仍能正确计算进度。
- 已完成任务重复完成仍按既有幂等语义处理，不因新校验制造无关失败。
- 学习与工作台入口覆盖相同不变量，跨用户关联仍被拒绝。
- 在专用隔离 MySQL 中验证成功和失败后的持久化结果；环境暂不可用时保留未验证项，交给 L4 补齐。
- 优先运行后端 tests.test_learning、tests.test_workspace；实际共享改动再补相关测试。修改前端时运行现有 pnpm typecheck 和 pnpm build，并记录可执行的手工操作。

交付最小差异、回归证据、规则表和阶段报告。报告列出 L2 需要沿用的终态规则，不开始 L2。
