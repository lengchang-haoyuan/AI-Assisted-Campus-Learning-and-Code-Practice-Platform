# AI 开发提示词使用说明

本目录把 `P00` 到 `P15` 的开发规划转换成可直接投喂给代码 AI 的独立提示词。当前 `ScholarHub` 还是从零开始的项目，因此必须严格按编号顺序执行。

## 使用方式

1. 先把当前项目根目录设置为 `C:\Users\Administrator\Desktop\毕业设计\ScholarHub`。
2. 每次只向 AI 投喂一个阶段文件，不要把多个阶段合并执行。
3. AI 开始前必须扫描当前代码和文档；阶段完成后先看懂修改，再执行启动、测试和手工验收。
4. 当前阶段通过后再进入下一个阶段。建议每个阶段单独提交一次 Git；当前目录若尚未初始化 Git，先由 AI 或你手动完成初始化。
5. 如果 AI 要新增依赖、修改已经确定的数据库结构、改变公共 API 或采用与文档不同的架构，先让它说明事实、风险、方案和推荐意见，得到确认后再实施。

## 所有阶段都必须遵守

- 安全性优先，其次是正确性，再考虑可读性和复用。
- 先检查现有实现和文档，再修改；空项目才创建基础结构。
- 只完成当前阶段，不提前实现后续阶段，也不顺手重构无关内容。
- 不硬编码密钥、密码、Token、数据库密码或机器专属路径；提供 `.env.example`，真实值只放本地环境变量。
- 外部输入必须在边界校验；前端校验不能代替后端校验；受保护资源必须在服务端校验所有权。
- 前端只通过 Axios 调用 FastAPI，不直接访问 MySQL；后端遵守 Router → Service → Repository → SQLAlchemy → MySQL 分层。
- AI 通过 AIProvider 抽象接入；模型输出必须当作不可信输入，使用 Pydantic 或等价 schema 校验，不允许无界循环或任意系统命令执行。
- API 使用 `/api/v1` 前缀、明确的请求和响应 Schema、稳定的错误语义；不要直接返回 ORM Model。
- 每完成一组功能立即验证。不能执行的检查要说明命令、原因和剩余风险，不能声称已通过。
- 汇报中不得输出密钥、Token、密码、完整敏感提示词、个人隐私或内部堆栈。

## 每阶段固定汇报格式

完成后必须汇报：

1. 修改和新增文件清单。
2. 本阶段关键设计和调用链。
3. 启动命令及必要环境变量。
4. 执行过的测试、Lint、类型检查、构建和结果。
5. 手工验收步骤和实际结果。
6. 未执行或失败的检查、已知问题和剩余风险。
7. 建议的 Git commit 信息。
