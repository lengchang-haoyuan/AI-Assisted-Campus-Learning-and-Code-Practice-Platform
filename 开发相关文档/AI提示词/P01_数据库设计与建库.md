# P01 数据库设计与建库：可直接投喂给 AI 的提示词

基于当前已完成的 P00 工程，继续开发 `ScholarHub` 的数据库层。本阶段只完成数据库设计、建库脚本和 SQLAlchemy Models，不实现业务 API。

## 本阶段目标

依据项目说明和现有 ER 设计建立 MySQL 数据库、`schema.sql` 和 SQLAlchemy Models。核心实体包括：`User`、`Project`、`Tag`、`Comment`、`Like`、`Favorite`、`Workflow`、`WorkflowNode`、`WorkflowEdge`、`WorkflowRun`、`AIRequest`、`AIResult`、`LearningPlan`、`DailyTask`、`Course`、`LearningRecord`、`LearningReport`。

必须明确主键、外键、唯一约束、索引、时间字段、JSON 字段、枚举或状态值、删除语义和用户/项目所有权关系。密码只能保存 hash；AI Key 不得进入数据库。数据库时间和 API 时间要有明确时区约定。

## 执行要求

1. 先检查 P00 产物、项目说明、前后端目录职责文档和当前配置。
2. 先输出 ER 关系、表职责、关键约束和疑难取舍，再编码。
3. `schema.sql` 与 SQLAlchemy Models 必须表达同一套结构，避免字段漂移。
4. Model 不承担 API Schema 职责；不要把密钥、密码明文或模型原始敏感输入写入数据库。
5. 迁移或建库脚本必须可审查；不要破坏已有数据，也不要重写已经发布的迁移。
6. 只完成数据库层，不实现注册登录、Project CRUD、Workflow 运行和 AI 调用。

## 验收标准

- 空 MySQL 数据库可按文档执行 `schema.sql`。
- 所有 Models 可以 import，Base metadata 能发现模型。
- SQLAlchemy 能依据环境变量建立连接或完成连接检查。
- 主键、外键、唯一约束和主要索引存在且有测试或结构检查证据。
- 至少验证用户、项目、学习、社区、Workflow 和 AI 记录之间的核心关系。

按固定格式汇报，建议提交：`feat: implement database schema and sqlalchemy models`。任何会改变已确定表结构的方案先暂停并说明兼容性影响。
