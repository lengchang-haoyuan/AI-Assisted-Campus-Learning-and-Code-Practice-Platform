# P18 班级与教学任务：可直接投喂给 AI 的提示词

基于已完成的 P17 校园身份和已确认的 P16 数据设计，实现班级、成员和教学任务。本阶段先建立教师布置任务、学生查看任务的闭环，不实现成果提交与教师反馈。

## 先检查现状

读取工作区规则、项目说明、前后端目录职责、AI 提示词 README、P16 方案与 P17 报告，检查现有个人 Course、DailyTask、Project、工作台和权限依赖。报告可复用内容，不把教师姓名字段视为教师授权。

沿用 Vue 3 + TypeScript + Element Plus、FastAPI + SQLAlchemy + MySQL 和现有分层。管理员、教师、学生共用前端；新增依赖、公共 API 或数据库变更先说明事实、兼容影响和推荐方案，等待确认后实施。

## 本阶段目标

- 教师在授权范围内创建、查看、编辑和归档班级；提供必要的成员加入、移除和列表接口，成员唯一，加入方式沿用 P16/P17 决策。
- 教师向所管理班级发布教学任务，至少包含标题、任务说明、学习目标、交付要求、截止时间和状态；可引用已有项目模板，但发布说明应有明确版本或快照语义。
- 学生查看自己已加入班级及已发布任务，支持稳定排序和有界分页；草稿任务对学生不可见，跨班级不能凭 ID 读取。
- 在现有前端增加最小班级列表、班级详情和任务详情入口，明确教师编辑状态与学生只读状态；不搭建独立门户。

## 业务与数据边界

1. 班级教学任务与个人 DailyTask 分离。未经确认不自动为每名学生复制个人任务，不回写学习时长、项目完成状态或私人课程。
2. 班级教师必须是已授权的有效教师账号；修改 owner、班级 ID 或成员 ID 不能转移权限。教师只能管理本人获授权班级，管理员只能执行 P16 明确允许的管理动作。
3. 按 P16 定义草稿、发布、关闭、归档和截止时间变更规则；发布后的需求修改应让学生能够识别，不静默改变已布置任务的验收标准。
4. 定义学生退出、被移除、教师停用和班级归档后的读取与写入权限；优先归档，不级联删除既有学习数据或为 P19 预留的成果历史。
5. 标题、说明、日期和状态由后端独立校验；数据库存 UTC，页面按明确时区展示截止时间。禁止无界成员列表和重复入班。

## 实现要求

遵循 `$frontend-backend-code-standards`，使用 Router → Service → Repository → Model，响应采用独立 Schema。迁移、Models 和 schema.sql 表达一致，不重写已发布迁移。

前端请求集中在 `src/api`，类型明确，表单防重复提交；加载、空、失败和重试状态完整。沿用现有视觉和液态标签等组件，动画不替代状态文字，支持键盘、窄屏和减少动态效果。不做 AI 出题、成绩册、自动排课或多学校管理。

## 验收标准

- 两位教师、两个班级和不同学生的隔离测试通过：教师 A 不能管理 B 班，学生不能浏览未加入班级，伪造关联 ID 被拒绝。
- 跑通教师建班 → 成员加入 → 保存草稿 → 发布任务 → 学生查看 → 修改截止时间 → 关闭或归档；刷新后来自真实数据库。
- 覆盖重复加入、无效教师、已归档班级、非法日期、分页边界、成员退出和发布后编辑的 API/Service 测试。
- 原个人课程、任务、Project CRUD 与社区功能保持兼容；没有用假统计补充班级页面。
