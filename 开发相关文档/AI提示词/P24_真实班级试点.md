# P24 真实班级试点：可直接投喂给 AI 的提示词

在 `ScholarHub` P23 技术准入通过、P16 关键决策已确认且校方批准试点后，协助开展一个班级的真实使用验证。本阶段主要是试点准备、证据收集、问题处理和复盘，不是继续扩张功能。

## 先核对准入

读取工作区规则、AI 提示词 README、P16 方案和确认记录、P17-P23 报告、当前部署与回退说明。核对教学负责人、技术值守、AI 预算、访问范围、数据处理规则、参与方式和退出安排，不从文档标题或 Git 提交推断已经批准。

建议规模为约 30-50 名学生、四周观察，但这只是规划假设；真实人数、周期和访问范围以校方确认及压测结果为准。没有真实教师、参与者或批准时，只输出待试点材料与阻塞项，不创建模拟记录冒充试点完成。

## 本阶段目标

1. 与负责人确认一门课程的实践目标，准备少量来源明确、教师审阅过的项目模板、操作指引和反馈入口，不把 AI 自动生成的材料标记为教师认可。
2. 制定邀请、入班、首次任务、成果提交、教师反馈、AI 使用、社区发布和退出流程，明确私有数据与自愿公开作品的边界。
3. 建立试点问题清单，记录问题影响、复现证据、优先级、处理人和验证结果。优先修复登录、权限、提交丢失、AI 失控费用和数据泄露等阻断问题。
4. 定义指标口径和观察周期：受邀与实际加入人数、活跃学习者、有效成果提交、获得反馈的提交、教师工作量、AI 成功率与用量/成本。数据必须来自实际记录或注明来源的问卷访谈。
5. 输出阶段性观察和期末复盘，明确继续试点、限范围修复、暂停或扩大的依据，不把增加功能数量当作成功指标。

## 评估原则

- 活跃、完成、有效反馈等指标先定义分母和去重规则；登录、点赞和自报学习时长不等于掌握知识。
- 区分真实行为数据、学生自述、教师评价、模型推断和供应商费用；计费不完整时说明未知范围，不用估算冒充账单。
- 若比较试点前后，说明样本与课程差异；没有对照或可靠证据时只报告观察，不宣称系统导致成绩提升或教师节省固定比例时间。
- 汇报使用必要的汇总或去标识信息，原始学生名单、联系方式、私人作品、访谈录音和秘密不得提交 Git；保留与访问遵守校方已确认规则。
- 学生拒绝非必要 AI 数据处理或作品公开时，应按已确认方案仍能完成允许的基础教学流程；不能暗中把课程提交发布到社区。

## 范围与执行要求

保持 Vue 3 + TypeScript + Element Plus、FastAPI + SQLAlchemy + MySQL 和已有 AI 架构。遵循 `$stop-that-shit` 与 `$frontend-backend-code-standards`；缺陷修复要有回归测试，不在试点中切换框架、加入复杂依赖或重做数据模型。

新增依赖、公共 API、数据库结构、部署或安全策略变化先说明影响并等待确认；高风险问题先按既定停用或回退方案保护用户，不擅自批量删库、改密码或重置所有账号。模型额度、发邀请、真实数据导入和对外联系按负责人授权执行，不因本提示词自动获得批量操作权限。

不自动安排无人值守的长期监控或报告发送；需要持续执行时由用户明确授权范围和频率。一次开发会话不能虚构四周观察，尚未发生的步骤保持未完成。

## 验收标准

- 准入、参与和教师审阅有真实可核对的确认；教师与学生实际跑通教学、AI 和社区的计划内流程。
- 完成已确认观察周期，记录留存使用、提交反馈、关键故障、费用和教师学生评价；没有足够证据时结论必须为待验证。
- 严重问题得到修复验证或有明确停用与处理决定；备份、值守和预算机制在试点期间实际可用。
- 复盘给出有证据的下一步，不默认扩到全校。阶段性准备材料可以交付，但不能标记整个 P24 完成。

## 最终汇报

按 `开发相关文档/AI提示词/README.md` 七项固定格式汇报，记录到 `开发相关文档/开发日志/开发操作日志.md` 和 `开发相关文档/阶段报告/`。增加试点时间范围、参与规模、数据来源、指标口径、人工确认、费用、故障和未完成项；不收录秘密或原始个人数据。

建议在完整试点结束后提交：`docs: record classroom pilot results`。准备期可提交明确标为准备或检查点的文档；缺陷修复单独提交，不使用最终结果提交伪装试点完成。按既有约定推送并核对远端。
