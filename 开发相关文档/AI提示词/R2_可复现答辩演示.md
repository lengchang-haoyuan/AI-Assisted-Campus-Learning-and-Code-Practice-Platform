# R2 可复现答辩演示：可直接投喂给 AI 的提示词

现在执行 ScholarHub [毕业设计整改方案](../开发规划/20260927-毕业设计整改方案.md)中的 **R2**。先读取 R0 范围页、R1 需求矩阵、根 README、数据库建库与迁移说明、现有[逐页演示指南](../答辩材料/ScholarHub原型逐页演示指南.md)，核对 Git 状态和本地环境。只处理毕业答辩主线的可复现演示。

## 本步目标

1. 设计最小的**虚构**演示数据：管理员、教师、学生、教学班、一个已发布任务、V1 提交、退回意见、V2 提交、通过反馈，以及主线需要的个人项目和学习记录。列明每条数据的角色、前置关系和演示用途。
2. 在动数据库前确认使用的是新建或专用隔离库，核对连接目标。不得清空、覆盖或迁移当前业务库，也不得复制真实账号、原始学生数据、数据库备份或密钥到 Git。若无法证明隔离，先写方案和初始化步骤，停止有风险的数据库写入。
3. 优先复用现有建库、受控管理员初始化和 API；制作最小的初始化步骤或脚本及清理方法。因演示必须修改公共 API、数据库结构、依赖或安全策略时，先说明证据、影响、方案与推荐并等待确认。
4. 从新建库验证“学生看到任务 → 提交 V1 → 教师退回 → 学生提交 V2 → 教师通过 → 双方查看版本与通知”；同时检查本人、跨班和管理员的数据访问边界。刷新后应仍可查询已保存结果。
5. 缩写一条 10–12 分钟的现场演示路径，附操作步骤、预期画面和失败时的备用截图。模型调用默认使用 Fake Provider 或已标注来源的历史记录；真实模型调用与费用必须另行明确授权。
6. 对整改方案 C2 给出当前版本可通过的主线验收。旧 `scripts.verify_integration` 用普通账号访问校园社区，已不符合 P17/P21 的身份和审核前置条件；先保留失败证据，再选择最小适配该脚本或交付等效的隔离验收步骤。不要删除断言或降低业务权限来获得通过。

## 交付与边界

- 演示步骤、样本数据说明和故障备用方案放在 `开发相关文档/答辩材料/`；可公开的脱敏截图放在 `开发相关文档/测试证据/`。
- 不创建真实教师或学生身份，不发邀请，不上线，不以虚构样本宣称真实课堂效果。
- 代码改动仅限让本步可复现演示通过的必要部分；遵循工作区 `AGENTS.md`、`$stop-that-shit` 和 `$frontend-backend-code-standards` 并按相关风险验证。

## 完成判据

- 另一环境按文档可以初始化虚构数据并走完主线，且不依赖原电脑的 74 个本地项目。
- 每一步有实际结果或明确的阻断原因；C2 有符合当前权限规则的通过证据或阻断结论。浏览器截图、API 测试和 Fake Provider 各自标明证据类型。
- 按现有目录约定追加中文时间索引操作记录和本步报告。用中文汇报文件、数据隔离证明、启动与验收命令、通过/失败、未执行项和恢复方法；不要提交或推送 Git。
