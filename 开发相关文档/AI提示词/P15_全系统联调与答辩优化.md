# P15 全系统联调与答辩优化：可直接投喂给 AI 的提示词

现在进入 `ScholarHub` 最终联调阶段。请基于 P00 到 P14 的实际代码做证据驱动的检查、修复和演示准备；不要把本阶段变成无边界重构或新增功能阶段。

## 必须跑通的演示链路

注册/登录 → 校园代码社区 → 项目创建或浏览 → 个人工作台 → Workflow 编辑 → ProjectContext → Agent → Prompt/需求分析 → 开发记录 → 学习记录 → 数据统计 → AI 学习报告 → 社区发布 → 点赞、评论、收藏和浏览。

## 联调检查范围

- API Base URL、CORS、JWT、Token 注入和 401/403/404/409/422/500 错误语义。
- 前后端字段、枚举、时间时区、分页、外键、所有权和删除语义。
- Workflow 节点、边、状态、Context 版本/stale、Provider 超时失败、Agent 结构化输出和 WorkflowRun。
- 数据库约束、索引、迁移/建库脚本、Redis 配置和没有 Redis 时的明确降级。
- 密钥安全、日志脱敏、输入大小、模型预算、提示注入、任意工具/命令执行风险。
- Windows 启动命令、`.env.example`、README、测试数据和答辩演示步骤。

## 测试要求

至少覆盖认证、Project、Community、Learning、Workflow、Context、Provider、Agent、Engine、Statistics 和 Report；按项目实际配置执行格式检查、Lint、类型检查、单元测试、集成测试、构建和关键手工验收。发现问题时优先修复本项目引入的错误，区分既有问题和本次问题，不删除测试或关闭检查来换取通过。

## 答辩材料要求

整理可用的简短解释：前后端分离、Axios/HTTP、Router-Service-Repository、Model/Schema、JWT、MySQL/Redis、Node/Edge/State、ProjectContext、Agent、Provider 和数据分析；每项都必须对应实际代码和可演示接口。明确记录尚未实现或使用简化方案的地方。

## 明确禁止新增

不要新增私信、好友、关注、在线 IDE、大规模代码执行、复杂 CI/CD、自研模型、复杂微服务或实时协同编辑。完成联调、文档、验证和答辩优化后，建议提交：`release: complete graduation project integration`。
