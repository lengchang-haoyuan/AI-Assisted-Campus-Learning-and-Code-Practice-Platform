# P02 FastAPI 后端基础架构：可直接投喂给 AI 的提示词

基于 P00 和 P01，建立 `ScholarHub` 的 FastAPI 后端分层架构。本阶段只做基础架构和健康运行，不实现具体业务功能。

## 本阶段目标

建立以下调用方向：`Router → Service → Repository → SQLAlchemy Model → MySQL`。实现并整理 `main.py`、`core/config.py`、`core/database.py`、`core/security.py`、`api/deps.py`、`api/v1`、`schemas`、`services`、`repositories`、`models` 的职责边界。

同时完成：统一 `/api/v1` 路由前缀、Swagger、统一异常处理、基础结构化日志、数据库 Session 依赖注入和 CORS 配置。数据库访问只能通过 Repository；Router 不写复杂业务和 SQL；Service 不拼接 SQL。

## 执行要求

1. 先检查 P00/P01 现状并报告目录和依赖，不重写可用代码。
2. DTO/Schema、领域业务对象和 ORM Model 分离；不要直接把 ORM Model 作为响应。
3. 统一错误响应，区分输入错误、未认证、禁止访问、未找到、冲突和内部错误；不向客户端暴露堆栈、SQL 或内部路径。
4. 配置从环境变量读取，启动时对必需配置给出可操作错误。
5. 本阶段不实现注册登录、Project CRUD、社区、学习、Workflow 执行和 AI Provider。

## 验收标准

- 后端启动无误，Swagger 可访问。
- `GET /api/v1/health` 仍然可用。
- 数据库 Session 可以通过 FastAPI 依赖注入获取和释放。
- 异常处理、日志和 CORS 经过最小测试。
- 分层调用方向清晰，没有 Router 直接访问 ORM/数据库的情况。

按固定格式汇报，建议提交：`feat: establish fastapi layered architecture`。
