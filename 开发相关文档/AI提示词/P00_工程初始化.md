# P00 工程初始化：可直接投喂给 AI 的提示词

你现在负责开发 `ScholarHub` 的第一个阶段。项目名称是“AI 辅助校园学习与代码实践平台”，定位是校园代码社区、个人学习工作台、可视化 AI 开发工作流和学习数据分析的综合平台。当前请从零开始，但必须先扫描工作区、已有文档和配置，不能凭空假设项目结构。

## 本阶段目标

只完成可运行的前后端工程骨架：

- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus。
- 后端：Python、FastAPI、Pydantic、SQLAlchemy。
- 配置 CORS、环境变量示例、统一 `/api/v1` 前缀。
- 实现 `GET /api/v1/health`，返回明确的健康状态和版本信息。
- 前端通过 Axios 真实请求 health API，并显示成功、加载和失败状态。
- 前后端都能启动，Swagger 可访问。

## 本阶段禁止

暂不实现登录、JWT、业务 CRUD、数据库业务表、社区、学习系统、AI、Agent、Workflow、统计和报告。不要为了未来功能提前创建空的复杂模块；只保留后续可以自然扩展的基础边界。

## 执行要求

1. 先报告当前目录结构、已有文件、可复用内容和空项目判断。
2. 先给出最小目录方案和启动方式，再编码。
3. 选择包管理器时依据实际锁文件；没有锁文件时说明选择理由，不要静默切换。
4. 配置使用环境变量和 `.env.example`，不得写入真实密钥。
5. 后端保留清晰的入口、配置、数据库占位和 API 路由边界；本阶段不要求连接业务数据库。
6. 前端的 API Base URL 必须可配置，不能把机器专属地址散落在组件中。
7. 每完成前端、后端、联调三组功能分别验证。

## 验收标准

- 后端可以启动，访问 `/docs` 能看到 health API。
- `GET /api/v1/health` 返回成功 JSON，错误时不泄露堆栈。
- 前端可以启动，页面通过 Axios 真实调用后端 health API。
- 前端能分别展示加载、成功和请求失败状态。
- 无硬编码秘密、无调试输出、无登录和业务功能越界实现。

## 最终汇报

按 `开发相关文档/AI提示词/README.md` 的固定格式汇报，并建议提交：`feat: initialize frontend and backend`。如果遇到需要新增依赖、改变工程方案或无法运行验证的情况，先说明事实、风险和推荐方案，不要隐瞒。
