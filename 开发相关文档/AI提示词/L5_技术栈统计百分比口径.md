现在执行 ScholarHub [闭环缺口清单](../开发规划/20260927-项目逻辑与代码闭环缺口清单.md)中的 **L5**。目标是让 percentage 的分母、API 文义、论文使用和测试一致，不扩展新的分析算法或改版图表。

## 源码与已知答案样例

读取 [统计 Repository](../../backend/app/repositories/statistics.py)、[统计 Service](../../backend/app/services/statistics.py)、[统计 API](../../backend/app/api/v1/statistics.py)、[Schema](../../backend/app/schemas/statistics.py)、[测试](../../backend/tests/test_statistics.py)、[前端类型](../../frontend/src/types/analytics.ts)与 [图表](../../frontend/src/views/AnalyticsView.vue)。

1. 确认查询按字段非空条件分组后取前 limit 项，Service 当前分母是否只是返回项计数之和。
2. 设计至少三类且超过 limit 的已知答案样本，例如 A=4、B=3、C=3，limit=2。前两项内部占比为 4/7、3/7，全量非空项目占比为 40%、30%。加入 null、空字符串、空白与同频排序样例，按实际查询定义核对。
3. 核对调用方是否使用 percentage；不能把“当前图表只用 count”写成百分比 API 没有问题。

## 先明确语义，再处理

两种可行方式：保留前 N 项内部占比并明确字段说明；或以当前维度全部有效非空项目为分母。推荐与论文和已确定产品需求一致的定义，说明兼容影响并按共同约束取得必要确认。

- 若论文只使用数量，可以限定论述；但必须明确 API 仍使用何种定义，不能仅删除说明掩盖歧义。
- 若采用全量分母，分母查询与分组过滤一致，先计算全量再截断结果；返回项占比之和可以低于 100%。不要把所有项目数混作每个维度的有效项目数。
- 保持统计范围准确：现有 statistics 图表是平台聚合，个人学习报告是当前用户聚合。没有需求不把平台 API 擅自改成个人 API。
- 不更改 count、排名和无数据语义，不新增依赖或迁移。

## 验收

超过 limit、多维度缺失值、零项目、同频稳定排序、不同 limit 的样例与确认定义一致；API 与使用说明不再有两种分母解释。保留 tests.test_statistics 回归；如修改前端类型/显示，执行现有类型检查和构建。隔离数据库核对实际 SQL 结果，未执行时交给 L4 补齐。

交付指标定义、最小差异或限定口径决定、已知答案样例和验证报告；不声称数量图表因此证明学习效果。
