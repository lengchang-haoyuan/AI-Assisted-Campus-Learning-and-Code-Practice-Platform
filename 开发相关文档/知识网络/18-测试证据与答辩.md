# 测试证据与答辩

功能是否实现看代码，是否验证看对应测试和报告，是否能面向学校使用还要看真实试点。不能互相替代。

## 验证入口

| 范围 | 现有文件或命令 |
| --- | --- |
| 后端单元/API | 在 `backend` 执行 `python -m unittest discover -s tests -q` |
| MySQL 结构 | `python -m scripts.verify_database_schema` |
| Context/Agent/引擎 | `verify_project_context.py`、`verify_agents.py`、`verify_workflow_engine.py` |
| 统计与报告 | `verify_statistics_reports.py` |
| 跨模块 | `python -m scripts.verify_integration`，默认 Fake Provider + 开发 MySQL |
| 前端类型与构建 | 在 `frontend` 执行 `pnpm typecheck`、`pnpm build` |
| 浏览器 | `frontend/scripts/verify-login.cjs`、`verify-session-report.cjs`、`verify-audit-regressions.cjs` |

数据库验收脚本会创建并清理隔离样本，使用开发库而不是生产库；Fake 模式不是“数据全是假的”，它只替代外部模型响应。

## 答辩路线

登录 → 社区 → 创建/浏览项目 → 个人工作台 → Workflow 保存并运行六类节点 → 查看历史结果 → 学习记录与报告 → 管理员邀请 → 教师建班和发布任务 → 学生查看任务。
