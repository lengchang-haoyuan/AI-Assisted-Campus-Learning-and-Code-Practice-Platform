# 产品定位与当前边界

ScholarHub 服务学生的项目实践与学习积累。[[07-项目管理]] 是主线，[[08-校园代码社区]] 用于分享交流，[[09-个人工作台]] 和 [[10-课程计划任务与记录]] 管理个人学习，AI 提供分析、规划提示与评审。

## 目前具备什么

| 层次 | 当前事实 |
| --- | --- |
| 可操作页面 | 认证、个人项目、社区、工作台、学习系统、Workflow 编辑与运行结果、统计报告、校园身份、账号管理、教学班和教学任务 |
| 后端能力 | Context、核心 Agent、六类节点执行引擎、校园身份和班级任务接口已存在 |
| 页面尚未闭环的部分 | 独立 Context/Agent 页面、学生成果提交与教师反馈尚未实现 |
| 案例内容 | 已向本地开发库录入 6 个开源学习案例和 50 道 Python 入门练习，来源材料随仓库保存；Git 不携带数据库记录 |
| 校园落地 | P17-P18 完成技术实现；P19-P24、真实教师确认、校方批准和真实班级试点仍未完成 |

## 不混淆的概念

- 创建 Project 保存的是项目资料和学习要求，不是上传并部署一个能自动运行的应用。
- 保存 Workflow 图不等于运行 AI；实际运行见 [[15-Workflow执行引擎]]。
- UI 动画、插画和空状态不能替代真实项目、学习记录或社区互动。
- Agent 是辅助学习与开发的工具，不执行任意 shell、SQL 或学生提交的程序。

内容补齐记录见 [[20-项目内容补齐]]；后续功能从 P19 成果提交与反馈开始，必须继续遵循 P16 的决策门槛。
