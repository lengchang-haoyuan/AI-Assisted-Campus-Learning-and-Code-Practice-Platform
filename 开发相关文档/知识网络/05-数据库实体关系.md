# 数据库实体关系

2026-09-07 同时比对 SQLAlchemy Models、`schema.sql` 和实际 MySQL，确认 **26 张表、51 个外键**一致。P17/P18 增量迁移已经应用到本地开发库。

## 表与职责

| 领域 | 表 | 关系 |
| --- | --- | --- |
| 账号 | `users` | 用户是个人项目、课程、学习与 AI 记录的归属边界 |
| 项目 | `projects`、`tags`、`project_tags` | User 一对多 Project，Project 与 Tag 多对多 |
| 社区 | `comments`、`likes`、`favorites`、`project_views` | 都关联 User 和 Project |
| 学习 | `courses`、`learning_plans`、`daily_tasks`、`learning_records` | 用户拥有课程/计划/任务/记录；计划可关联课程和项目，任务可关联计划和项目，记录可关联项目/课程/任务 |
| Workflow | `workflows`、`workflow_nodes`、`workflow_edges`、`workflow_runs` | Project 一对多 Workflow；Workflow 一对多节点、边与运行 |
| AI | `ai_requests`、`ai_results` | 请求可关联 Project/WorkflowRun；每个结果关联请求 |
| 报告 | `learning_reports` | 用户拥有报告，报告可通过唯一 `ai_result_id` 关联 AIResult |
| 校园身份 | `campus_memberships`、`campus_invitations`、`password_resets`、`account_audits` | 普通账号与固定校园角色分离；邀请、重置和管理动作可审计 |
| 教学 | `teaching_classes`、`class_memberships`、`teaching_assignments` | 教学班包含独立成员关系和任务；不复用个人 Course、DailyTask 或 Project 权限 |

[[12-ProjectContext上下文]] 存在 `projects.context_data` JSON 中，**没有额外的 ProjectContext 表**。

## 关键约束

- 用户名、邮箱唯一；密码只保存 hash，AI Key 不进入业务表。
- 点赞和收藏各自具有 `(user_id, project_id)` 唯一约束。
- Workflow 名称在同一 Project 内唯一；节点 `node_key` 在同一 Workflow 内唯一。
- WorkflowEdge 使用包含 `workflow_id` 的复合外键，防止连接到别的图；唯一约束和检查约束限制重复边与自环。无环检查仍由 Service 承担。
- 学习报告的 `(user_id, period_start, period_end)` 唯一，防止同周期无控重复记录。
- 校园成员一名用户唯一，班级成员在 `(class_id, campus_membership_id)` 上唯一；任务使用状态和 revision 约束并发写入。
- 时间线查询围绕 owner/user、状态和时间字段建索引，进度具有范围约束。

## 删除与时间

所有权类外键常使用 `RESTRICT`，不能随便删除被引用用户；项目删除会级联 Workflow 和社区子数据，学习记录等可选项目引用使用 `SET NULL` 保留记录。不能把所有关系笼统理解成级联删除。

MySQL `DATETIME(6)` 保存 UTC；`UTCDateTime` 在 Python/API 边界恢复带时区的时间。统计日界线见 [[16-统计与AI学习报告]]。
