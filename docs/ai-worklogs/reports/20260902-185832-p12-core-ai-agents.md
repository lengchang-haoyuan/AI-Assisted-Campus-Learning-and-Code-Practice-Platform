## 需求摘要

在 P10 ProjectContext 和 P11 AI Provider 基础上实现统一 `BaseAgent`，优先交付 `ProjectAnalysisAgent`、`PromptAgent` 和 `ProjectReviewAgent`。Agent 只负责经过边界校验的模型编排，不直接操作数据库；Service 负责保存 `AIRequest`/`AIResult`。系统规则、用户输入、Context 和模型输出必须分界，限制输入、单回合、超时和 Token，不执行模型生成的 shell、SQL 或工具命令。本阶段不实现 Workflow Engine。

## 本阶段关键设计和调用链

- 调用链：`Router → AgentService → BaseAgent → AIClient → AIProvider → DeepSeek`；持久化链为 `AgentService → AgentRepository → AIRequest/AIResult → MySQL`。
- Agent 不依赖 Session、Repository、FastAPI 或供应商 HTTP 对象；Router 不访问 ORM，Repository 不调用模型。
- `AIRequest` 在外部调用前先提交为 `running`，远程调用不包在数据库事务中；成功时 AIResult 与 `completed` 状态原子提交，已知失败写为 `failed`。
- 输入只保存规范化 JSON 的 SHA-256 哈希、安全摘要、字节数、Context 版本和回合数，不保存原始用户输入。
- 系统消息只放不可变规则和输出 Schema；ProjectContext 与用户输入只放在用户消息的独立、不可信 JSON 区块中。
- Agent 请求固定一个模型回合，使用 DeepSeek 原生 `json_object` 模式并关闭 thinking；模型 JSON 仍必须通过 Pydantic Schema，格式错误不重试也不伪造成功。
- `PromptAgent` 的必要项目字段由已验证 Context 和输入确定性拼装，模型只提供实施指导、验收标准和风险说明，避免遗漏既定技术边界。
- 只实现三个优先 Agent。LearningPlanAgent、LearningReportAgent、WorkflowAgent 和 Workflow Engine 未进入本阶段。

## 兼容性与安全影响

- 公共 API：新增 `POST /api/v1/agents/project-analysis`、`POST /api/v1/agents/prompt`、`POST /api/v1/agents/project-review` 和 `GET /api/v1/agents/results/{request_id}`；P00-P11 API 保持不变。
- 数据与迁移：复用既有 `projects.context_data`、`ai_requests` 和 `ai_results`；未修改 Schema、Models、外键、索引、枚举或迁移历史。
- 依赖：未新增、升级或替换第三方依赖。
- 权限：运行前校验 Project 所有权，结果查询同时按 `request_id` 和当前 `user_id` 过滤；Context 与 Project 核心字段漂移时返回 409。
- 秘密与隐私：明显的 API Key、密码、Secret、Bearer Token 在输入和模型输出 Schema 边界均被拒绝；日志和报告不含密钥、Authorization、完整 Prompt、模型正文或个人数据。
- 命令安全：Agent 没有工具注册和命令执行路径，模型内容只作为待校验数据，不可提升权限。

## 手工验收步骤和实际结果

1. 为已有 Project 创建或同步 ProjectContext，使用登录 Token 调用对应 Agent 运行接口。
2. 本次真实 DeepSeek 验收中，ProjectAnalysisAgent 返回 4 项需求拆解和 8 个连续步骤，耗时 10599 ms，使用 1112 prompt tokens 和 1710 completion tokens。
3. PromptAgent 返回 10 项验收标准，确定性生成的开发 Prompt 为 2807 字符，耗时 4664 ms，使用 565 prompt tokens 和 535 completion tokens。
4. 使用 Fake Provider 执行 MySQL 脚本后，分析与 Prompt 的 `AIRequest.status` 均为 `completed`，`AIResult` 可重新查询；其他用户查询返回不存在语义。
5. 验收脚本结束后确认 `p12_verify_*` 临时用户和对应请求数量均为 0。

- Ruff、Mypy、Pytest 未运行：仓库未声明这些配置或依赖，项目标准测试命令为 `unittest`；未擅自新增检查依赖或修改测试策略。
- 前端类型检查、构建和浏览器验收未运行：P12 未修改前端文件或既有前后端契约。
- 进程在 `AIRequest` 提交后、Agent 完成前异常终止时，可能留下 `running` 记录；普通取消、Provider、解析和内部处理失败已标记为 `failed`，跨进程恢复策略应由 P13 执行引擎统一处理。
