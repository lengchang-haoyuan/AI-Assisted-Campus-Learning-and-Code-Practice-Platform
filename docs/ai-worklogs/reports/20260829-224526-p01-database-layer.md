## 2. 本阶段关键设计和调用链

- ER 主链：`User -> Project -> Workflow -> WorkflowRun -> AIRequest -> AIResult`；项目关联 Tag、Comment、Like、Favorite；用户关联 Course、LearningPlan、DailyTask、LearningRecord、LearningReport。
- 社区行为直接归属 Project，不提前增加 Post；Project 与 Tag 使用 `project_tags` 多对多表。
- WorkflowEdge 使用两组复合外键 `(node_id, workflow_id)`，从数据库层保证源节点和目标节点属于同一 Workflow。
- 状态采用 `VARCHAR + CHECK`，便于后续演进且避免 MySQL 原生 ENUM 迁移成本；JSON 只用于结构可变的配置、快照和分析结果。
- 删除语义：用户拥有的核心数据使用 `RESTRICT`；项目内部 Workflow 和社区关系使用 `CASCADE`；学习历史、AI 运行来源等可选引用使用 `SET NULL`。
- `User` 只保存 `password_hash`；`AIRequest` 只保存输入哈希、脱敏摘要和计量元数据，不保存 API Key、原始提示词或原始敏感输入。
- 时间约定：MySQL 保存 UTC `DATETIME(6)`；连接会话固定 `+00:00`；Python ORM 边界拒绝无时区时间并返回 UTC-aware `datetime`。
- 连接链：`.env/DATABASE_URL -> Settings -> get_engine -> sessionmaker/check_database_connection`。Engine 延迟创建，health API 启动不隐式连接数据库。

## 3. 启动命令及必要环境变量

空库初始化：

```powershell
cd backend
mysql --user=root --password --execute="source schema.sql"
```

本地 `.env` 至少配置以下变量，密码必须 URL 编码且不得提交：

```dotenv
DATABASE_URL=mysql+pymysql://用户名:URL编码后的密码@127.0.0.1:3306/scholarhub?charset=utf8mb4
```

连接与结构检查：

```powershell
.\.venv\Scripts\Activate.ps1
python -m scripts.check_database
python -m scripts.verify_database_schema
```
