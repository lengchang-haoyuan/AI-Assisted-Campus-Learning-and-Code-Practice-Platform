## 需求摘要

在 P10 ProjectContext 基础上建立 `AIService/AIClient/AIProvider` 统一调用边界，选择一个已配置供应商并完成真实最小调用。统一处理模型参数、输入输出、连接与总超时、取消、网络错误、模型错误、限流、响应格式和受限重试；日志只记录必要元数据。本阶段不实现 Agent、Workflow Engine、Prompt 模板、工具调用或 AI 请求持久化。

## 修改内容

- 新增统一消息、请求、Provider 结果、Client 结果、Token 使用量和失败类别模型。
- 新增 `DeepSeekProvider`，使用官方 HTTPS API 和 `httpx.AsyncClient`，不把 HTTPX 对象或供应商原始 JSON扩散到 Service/Router。
- 新增 `AIClient` 总超时、取消传播、失败分类、指数退避与抖动；只重试连接前失败和明确返回的 429，且受次数、延迟和总超时限制。
- 新增 `AIService`，把供应商错误映射为稳定的 502/503/504 应用错误。
- 新增受 JWT 保护的 `POST /api/v1/ai/test`，请求和响应使用独立 Pydantic Schema。
- 新增 DeepSeek 环境变量示例、配置校验和结构化 AI 日志字段；密钥缺失不阻止应用启动。
- 新增 14 项 P11 测试，覆盖 Fake Provider、DeepSeek HTTP Mock、真实边界、重试、超时、取消、格式错误、限流、配置脱敏、认证和 API 映射。

## 关键设计决定

- 决定：首个 Provider 使用 DeepSeek，默认模型为 `deepseek-v4-flash`，HTTP 客户端使用 `httpx>=0.28,<1.0`，不安装供应商 SDK。
- 原因：当前本机存在 DeepSeek 配置，HTTPX 能提供异步调用、细粒度网络超时、取消和 MockTransport 测试，同时保持供应商响应隔离。
- 决定：`DEEPSEEK_API_KEY` 可空，应用和 Swagger 正常启动；只有实际调用时返回 `503 ai_configuration_error`。
- 原因：健康运行不应被尚未配置的可选外部服务阻断，也不能在无密钥时伪造成功。
- 决定：只自动重试连接超时、连接失败和明确返回的 429；读写超时、5xx、模型错误和格式错误不自动重试。
- 原因：这些失败可能已经被上游处理，自动重复可能产生重复计费或不明确副作用。429 的 `Retry-After` 超过本地最大延迟时直接失败，不违规缩短等待。
- 决定：HTTPX Client 通过 FastAPI 异步生成器依赖按请求创建并在 `finally` 语义下关闭；总超时覆盖 Provider 调用、重试和等待。
- 用户确认：用户已明确确认 DeepSeek 推荐方案及新增 `httpx>=0.28,<1.0`；实际安装版本为 `0.28.1`。

## 兼容性与安全影响

- 公共 API：新增 `POST /api/v1/ai/test`，不修改 P00-P10 已有请求、响应或状态码。
- 数据与迁移：不修改 `schema.sql`、SQLAlchemy Models、18 张表或迁移历史；不写入 `AIRequest`、`AIResult` 或其他业务数据。
- 权限：测试接口要求当前 JWT 用户；路由守卫之外仍由后端 `CurrentUser` 依赖认证。
- 输入与输出：Prompt 限制 1-4000 字符，模型名、temperature 和 max_tokens 均有界；供应商 JSON 作为不可信输入经过 Pydantic 校验，空内容或异常格式不会伪造成功。
- 密钥与隐私：密钥使用 `SecretStr` 且只从环境变量读取；`.env` 已被 Git 忽略。日志不记录密钥、Authorization、完整 Prompt、模型正文或个人数据。
- 网络：DeepSeek Base URL 固定为 `https://api.deepseek.com`，关闭重定向跟随，避免凭据被转发到非预期地址。

## 手工验收步骤和实际结果

1. 在未提交的 `backend/.env` 中配置 `DEEPSEEK_API_KEY`，不要把密钥写入 `.env.example`。
2. 执行 `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`。
3. 在 Swagger 登录并设置 Bearer Token，调用 `POST /api/v1/ai/test`，请求体可使用 `{"prompt":"只回复 OK","temperature":0,"max_tokens":64}`。
4. 本次实际验收使用进程内 ASGI 请求运行相同路由，并以隔离身份依赖避免写入数据库；返回 200、`provider=deepseek`、`model=deepseek-v4-flash`、`finish_reason=stop`、`content` 非空和带请求 ID。
5. API 的缺少 Token、无效输入和缺失密钥分别由测试验证为 401、422 和 503，均使用统一错误结构。

## 剩余风险与后续建议

- 真实供应商行为受网络、账户额度、模型可用性和上游限流影响；当前成功结果证明本机配置与 P11 边界可用，不代表外部服务永久可用。
