## 需求摘要

从空业务项目建立 Vue 3 + TypeScript + Vite 前端与 FastAPI + Pydantic + SQLAlchemy 后端，实现可配置 CORS、环境变量示例、统一 `/api/v1` 前缀、health API，以及前端通过 Axios 展示加载、成功和失败状态。明确不实现认证、CRUD、业务表、社区、学习系统、AI、Agent、Workflow 和统计。

## 修改内容

- 新增前端工程，接入 Vue Router、Pinia、Axios 和 Element Plus。
- 新增后端工程，提供配置模块、SQLAlchemy 延迟建连占位、版本化路由和 FastAPI 入口。
- 实现 `GET /api/v1/health`，返回服务状态、名称和版本。
- 实现前端健康状态页，支持加载、成功、失败、重试、请求取消和响应式布局。
- 新增前后端 `.env.example`、根目录 `.gitignore` 和启动 README。

## 文件与架构变化

- `frontend/src/api/`：集中 Axios 客户端和 health 请求。
- `frontend/src/stores/health.ts`：管理健康检查异步状态和竞态取消。
- `frontend/src/views/HomeView.vue`：展示真实 API 状态，不承载底层请求配置。
- `backend/app/core/config.py`：集中读取环境配置和 CORS 来源。
- `backend/app/core/database.py`：仅提供 SQLAlchemy 引擎工厂，P00 不主动连接数据库。
- `backend/app/api/v1/`：维护 `/api/v1` 下的 health 路由。
- `backend/app/main.py`：创建 FastAPI、配置 CORS 并挂载版本化路由。
- 依赖方向：Vue 页面 → Pinia → Axios → FastAPI Router；数据库能力保持延迟边界，没有业务模型或跨层访问。

## 关键设计决定

- 决定：没有锁文件时选择 pnpm，并提交 `pnpm-lock.yaml`。
- 原因：本机 pnpm 11 可用，锁文件便于后续阶段复现依赖。
- 用户确认：用户已明确要求使用 Vue、Vite、Router、Pinia、Axios 和 Element Plus。
- 决定：TypeScript 固定为 5.9.3。
- 原因：自动解析的 TypeScript 7.0.2 与 vue-tsc 3.3.11 不兼容；5.9.3 可通过完整 Vue 类型检查。
- 用户确认：依赖版本调整通过执行前权限确认。
- 决定：Element Plus 采用手工按需注册。
- 原因：不增加自动导入依赖，将主 JS 构建体积从约 1.0 MB 降至约 153 KB。

## 兼容性与安全影响

- 公共 API：新增 `GET /api/v1/health`，没有变更既有 API。
- 数据与迁移：无数据库连接、业务表或迁移。
- 权限、秘密和隐私：配置来自环境变量；示例文件不含真实秘密；源码扫描未发现疑似硬编码凭据或敏感日志。
- CORS：仅允许环境变量配置的本地前端来源；当前只开放 health 所需的 GET 和基础请求头。
