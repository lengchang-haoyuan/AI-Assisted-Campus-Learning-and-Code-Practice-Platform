# 任务完成报告：P04 项目管理 CRUD

- 完成时间：2026-08-30 09:39:12 +08:00
- 任务范围：后端 Project REST API
- 项目根目录：`ScholarHub`

## 需求摘要

基于 P00-P03 实现登录用户的 Project 创建、列表、详情、更新和删除。owner 必须来自当前 JWT 用户，资源读取和写入必须校验所有权；列表要求有界分页、稳定排序和明确空数据语义。本阶段不实现前端页面、社区互动、Workflow 执行或 AI 功能。

## 修改内容

- 实现 `GET/POST /api/v1/projects` 和 `GET/PUT/DELETE /api/v1/projects/{project_id}`。
- Project 请求和响应覆盖名称、描述、难度、技术栈、需求、输出要求、owner、状态和 UTC 时间字段。
- 创建时只使用当前用户 ID；请求中的 `owner` 或 `owner_id` 因额外字段校验返回 422。
- 列表仅查询当前用户，按 `created_at DESC, id DESC` 排序，分页边界为 `page 1..10000` 和 `page_size 1..100`。
- 详情、更新和删除统一在 Service 中检查项目存在性与 owner，分别返回 404 或 403。
- 数据库完整性冲突转换为 409，其他未预期异常继续由统一异常处理返回脱敏 500。
- CORS 增加 P04 所需的 PUT 和 DELETE 方法。

## 文件与架构变化

- `backend/app/schemas/project.py`：Project Create、Update、Response、List Response 和字段边界校验。
- `backend/app/repositories/project.py`：owner 范围计数/列表、详情、写入和删除。
- `backend/app/services/project.py`：领域数据、分页、所有权规则和错误转换。
- `backend/app/api/v1/projects.py`：认证接入、参数解析、Service 调用和响应映射。
- `backend/app/api/deps.py`、`presenters.py`、`router.py`：Project 依赖注入、DTO 映射和路由注册。
- `backend/tests/test_project.py`：Project API 与 Service 测试。
- 依赖方向保持 `Router -> Service -> Repository -> Project Model -> MySQL`；Router 不引用 ORM 或 SQLAlchemy，Response 不直接暴露 ORM。

## 关键设计决定

- 决定：复用 P01 已发布的 `projects` 表，不修改表结构和迁移。
- 原因：现有表已经包含 P04 所需字段、owner 外键、状态/难度约束、索引和时间字段。
- 用户确认：不需要；没有发生数据库结构变更。
- 决定：管理列表只返回当前用户拥有的项目，owner 以 `{id, username}` 返回。
- 原因：P04 是个人项目管理，避免跨用户数据泄露，同时满足 owner 响应要求。
- 用户确认：不需要；直接落实所有接口登录和所有权约束。
- 决定：`PUT` 接受部分字段，但拒绝空请求；显式 `null` 仅用于数据库可空字段。
- 原因：与规划中的 `ProjectUpdate` 和后续表单编辑兼容，同时避免空更新和不可空字段被清除。
- 用户确认：不需要；不改变既有 API，因为 P04 是该接口首次实现。

## 兼容性与安全影响

- 公共 API：按 P04 要求新增五个 Project 接口；既有 health、auth 和 users 接口不变。
- 数据与迁移：没有修改 `schema.sql`、Models 或已发布数据；删除沿用 P01 已定义的外键删除语义。
- 依赖：未新增或升级第三方依赖。
- 权限：所有路由使用 `CurrentUser`；列表按 owner 查询，详情、更新和删除在 Service 中强制比对 owner。
- 输入：字段长度、难度、状态、项目 ID、分页和 requirements 数量/序列化大小均有边界；额外字段禁止。
- 隐私：Project owner 响应只包含用户 ID 和用户名，不暴露邮箱、密码哈希或 Token。
